# Makosh engineering

- Read `docs/development-status.md`, then verify Git and current source. Preserve unrelated changes.
- Native SwiftUI/AppKit, macOS 26+, Apple Silicon. No Electron/Tauri product shell.
- Follow the selected references' verified layouts and workflows; do not invent a replacement interface. Telegram follows TelegramSwift; mail uses MMail functionality and Aether Courier visuals. Confirm each changed screen against current reference source/screenshots and record remaining differences in `docs/reference-interface.md`.
- Contacts need the local PostgreSQL service, without communication accounts. Never read personal accounts, mail, system Contacts or messages without separate explicit authorization. Examples and UI QA use synthetic data and an isolated schema selected through `--database-config`.
- Before architecture/module work and debugging, actively search the selected references and Makosh with XERJ; confirm hits against source. Read `docs/xerj.md`. Check commit SHA and content fingerprints before reusing an index; refresh changed scopes. Report actual failures, never substitute `rg` as XERJ evidence. Keep machine indexes/configuration in ignored `.local/`.
- Do not copy third-party code without exact license and dependency review. The Telegram engine uses the reviewed iOS revision selected from TelegramSwift, independently pinned in `Dependencies/TelegramEngine.lock.json`; build/run/test must never depend on `.references/`. See `docs/telegram.md` and `THIRD_PARTY_NOTICES.md`. Own code retains MIT; the combined app is GPLv3. Never copy the outer GPLv2-only UI or embedded API credentials. Never enable engine logs containing private account data.
- Identity is (service, accountID, externalID). Imports, merges and undo must be atomic. Preserve manual overrides, source observations, identities and notes. Undo must stop after later edits; revision reuse must never enable stale undo.
- Use no more than two same-model subagents. Assign disjoint files; root alone changes manifests, integration docs, Git and publication.
- Run `scripts/dev-db.sh up`, `scripts/test.sh`, `scripts/build-app.sh`, and inspect actual UI for changed flows. Build/test scripts prepare pinned engine and flatc source and supply libpq/OpenSSL 3 configuration; integration tests require real PostgreSQL. Never edit ignored generated engine files directly: change the reviewed preparation recipe. Account authorization is user-entered in the app and remains separately scoped. Compilation is not runtime proof. Keep `docs/development-status.md` current with actual results and remaining blockers.
