# Раздел «Файлы» и Paperless

Дизайн: `superpowers/specs/2026-11-06-files-section-paperless-design.md`;
план: `superpowers/plans/2026-11-06-files-section-paperless.md`. Это первая из
трёх частей файлового направления; SMB/S3 как источники и адресаты (часть 2)
и пересылка в чаты/письма и карточки ИИ (часть 3) здесь не реализованы.

## Что это

Единое место для всех вложений, которые прошли через каналы Макоша и были
сохранены в архив (PostgreSQL `archive_file_events` + внутренний S3), плюс
подключения Paperless-ngx: просмотр его архива и загрузка туда любого файла
из письма, чата Telegram/WhatsApp, файла Teams или самого каталога.

## Модуль `MakoshFiles`

- `FileCatalogue` (actor) читает `archive_file_events` курсором
  (`MessageArchiveStore.fileEvents(after:limit:)`, только `stored`), оставляет
  последнюю запись на вложение, пропускает `rfc822-source` (копия письма
  целиком) и берёт дату/автора сообщения одним запросом по `message_token`
  (`latestRecord(identity:)`, индекс `archive_message_sequence`). Названия чатов
  и писем даёт `FileSourceResolving`, который приложение реализует над
  моделями сервисов (`FileSourceBridge`). Байты каталог не держит.
- `FileHandoff` — единая передача файла адресату: имя, размер, дата и
  замыкание, которое пишет байты в закрытый каталог 0700.
- `PaperlessConnection`/`FileStorageRegistry` — подключения в UserDefaults
  (`makosh.files.storages.v1`, без секретов); `FileStorageTokenVault` — токены
  только в Связке ключей (`org.makosh.files.tokens.v1`).
- `PaperlessClient` — REST по HTTPS (http только loopback), редиректы не
  выполняются, `Authorization: Token …`, `Accept: application/json; version=9`
  с повтором без версии на `406`; `401/403` → «не принял токен», `413` → «сервер
  не принимает файл такого размера», не-JSON → «ответил не так, как
  ожидалось»; тексты ошибок не содержат токена. Загрузка — multipart через
  временный файл, до 512 МиБ.
- `PaperlessSender` (actor) — экспорт → загрузка → опрос задачи каждые 2 с до
  3 минут; журнал `Application Support/Makosh/PaperlessSubmissions.json`
  (0600) хранит каждую попытку, при старте незавершённые дозапрашиваются по
  `taskID`. Отказ Paperless по контрольной сумме показывается как «Такой
  документ уже есть». Потеря ответа на загрузку — состояние «неизвестно»;
  ничего не повторяется автоматически.
- `FilesWorkspaceModel` (MainActor) — источник (все/сервис/хранилище), поиск,
  фильтр по категории, сортировка, документы Paperless постранично, отправки.
  Каждая загрузка помнит поколение выбора и отбрасывает поздний результат.

## Приложение

- Раздел «Файлы» (`Destination.files`): боковая колонка с источниками и
  хранилищами («+» открывает редактор), таблица файлов с поиском и
  фильтрами; контекстное меню: Посмотреть (Quick Look через
  `FilePreviewLease`, каталог 0700/файл 0600, удаляется при закрытии),
  Сохранить как…, Открыть источник, Отправить в Paperless….
- Хранилище в боковой колонке открывает архив Paperless: поиск, страницы,
  Посмотреть/Сохранить оригинал, Открыть в Paperless.
- Настройки → Файлы: список подключений, проверка, редактор (название, адрес,
  токен, тип документа и теги по умолчанию).
- `FileSendMenu` — пункт «Отправить в Paperless…» у плитки вложения письма,
  у загруженного файла Telegram, у сообщения WhatsApp с файлом, у файла
  Teams и у строки каталога; без подключений — «Подключить Paperless…».
  Лист отправки показывает ход: Загружается → Обрабатывается → Документ
  принят · #id (Открыть в Paperless) / Такой документ уже есть / Результат
  неизвестен (Проверить).
- Документы Paperless не попадают ни в контекст ИИ, ни в индекс ИИ.

## Проверки

- `Tests/MakoshFilesTests`: каталог на реальном PostgreSQL, подключения и
  токены (фальшивая Связка ключей), клиент против `URLProtocol`-заглушки,
  отправитель с журналом, модель раздела, аренда предпросмотра, изоляция QA.
- Синтетический QA: `python3 scripts/run-files-qa.py --launch` собирает
  отдельный бандл `MakoshFilesQA.app` и запускает его с
  `--files-synthetic-preview --database-config <абсолютный путь>` в схему
  `qa_files_…`: шесть файлов четырёх сервисов, подставной Paperless (три
  документа, любая загрузка принимается как #7). Настоящие аккаунты, сеть и
  Связка ключей не используются.
- Живая проверка с настоящим Paperless (`https://doc.sh-inc.dev`, только
  токен) выполняется по команде пользователя одним файлом; токен создаётся в
  профиле Paperless.
