# Перенос почты MMail / Aether

Принятый объём: отдельный SwiftPM mail adapter с IMAP/SMTP/MIME из MMail
`69bf8c9b2436d7d000652f41362f8fdebf406599`, встроенный в общий workspace.
Визуальный источник — Aether Courier `8ab37e1da22363744be5d7b019f4300d8238d625`:
папки, список, чтение, фиолетовое выделение, крупная тема и компактные адреса.
Вместо Copilot справа используется досье Макоша. Выбор сервиса сохраняется.

## Порядок реализации

1. Независимый продуктовый lock/licences, SwiftPM transport и MIME. Проверить
   бинарные MIME-вложения, границы заголовков, UIDVALIDITY, command correlation,
   bounded responses/timeouts, неизвестный SMTP DATA/IMAP APPEND без auto retry.
2. Account worker: Keychain, PostgreSQL metadata, encrypted archive/S3,
   account/folder/generation isolation, reconnect, paging, search, flags/move,
   persisted drafts/outbox. Ключ письма включает account/folder/UIDVALIDITY/UID.
3. Нативные account/folder/list/reader/compose формы по Aether внутри workspace;
   plain/HTML с запрещёнными remote resources, attachments, reply/forward,
   связь отправителя с досье. Протокол/SQL/MIME/Keychain вне MainActor.
4. Scripted protocol, PostgreSQL/S3 и synthetic native UI проверки; общие test
   и signed bundle build. Текущие изменения Telegram сохранить.

## Критерии и ограничения

Решение пользователя 2026-10-15: календарь и OAuth исключены из объёма.
Остальные пункты завершения выполняются по
`docs/superpowers/plans/2026-10-15-mail-completion.md`; пауза живой QA сохраняется.

Реальная почта требует отдельно выбранного пользователем аккаунта/действий;
пауза живой QA сохраняется. OAuth не поставляется выбранным MMail и требует
отдельной provider-specific интеграции. SMTP acceptance означает принятие
сервером, а не доставку/прочтение. При неизвестном исходе повтор запрещён до
явного разрешения. Полученное содержимое и версии сохраняются независимо от
remote удаления. Файлы не записываются байтами в PostgreSQL.

Статус/доказательства каждого шага: `docs/development-status.md`.

## Реализованные адаптации

Точный `Dependencies/Mail.lock.json` проверяется при build/test вместе с
`Package.resolved` и лицензиями. Нелинкуемый swift-nio-ssl оставлен только в
upstream dependency graph; собственный NIO TLS handler использует уже выбранный
OpenSSL 3, обязательные trust/hostname checks, TLS 1.2+. Никакой `.references`
зависимости сборки или исполнения нет.

MailRepository шифрует state, отдельные полные письма и короткие previews;
append-only versions не допускают UPDATE/DELETE/TRUNCATE. Cache paging имеет
folder/current UIDVALIDITY/removed predicates и независимый курсор. Старые
поколения доступны в общем архиве. Поиск текста на сервере, flags/MOVE, ответ,
пересылка, full body/plain/HTML, файлы и досье реализованы. Raw RFC822 и файлы
попадают в encrypted S3, для папок по умолчанию ON. OFF запрещает любые новые
S3-копии, в том числе при подготовке отправки; файлы черновика восстанавливаются
из зашифрованной локальной подготовки. Сохранение raw письма при OFF также
отключено; полные text/HTML версии остаются в encrypted PostgreSQL.

Drafts сначала сохраняются локально, затем один APPEND при активном аккаунте.
Неизменённый подтверждённый черновик не создаёт новую копию. Изменённая версия
может создать новую remote copy; старые версии сохраняются. Утрата подтверждения
блокирует новый APPEND до явной проверки в «Исходящих операциях». Remote Drafts
открываются в редакторе; файлы копируются через S3/локальную подготовку. Sent
APPEND после SMTP никогда не вызывает повтор SMTP.

Общий вид воспроизводит актуальный Aether backdrop, три панели и paper reader.
Вместо Copilot — досье. Rich text toolbar адаптирован из MMail; RTF хранит только
форматирование, встроенные бинарные вложения запрещены. HTML reader имеет CSP,
nonpersistent WKWebView, JS disabled, no remote resources; внешний переход
требует явного подтверждения адреса. MainActor не выполняет protocol/SQL/MIME/
Keychain/crypto/file preparation.

Уведомления новых непрочитанных INBOX писем используют MMail Notifier/AppModel:
первая загрузка и смена UIDVALIDITY устанавливают baseline, поиск/старые страницы
не уведомляют. Курсор, настройки и ограниченная очередь сохраняются зашифрованно
в той же транзакции PostgreSQL, что и письма; два окна забирают событие один раз.
Общий macOS delegate обслуживает Telegram и почту с отдельными namespace и
непрозрачными токенами. Начальное разрешение запрашивается один раз на приложение;
отказ/ошибка допускают только явный повтор. После callback заново проверяются
аккаунт, текущая папка/поколение, unread, настройки, собственное окно и блокировка
экрана. Это системная приватность, а не исключённая из продукта автоблокировка.

Настройки show/preview/sound доступны для всей почты, аккаунта, папки и отправителя
внутри аккаунта. Ограничения складываются: локальное ON не отменяет родительский
OFF. Foreground ON соответствует MMail и отключается пользователем. Архив/Корзина
из карточки выполняют один MOVE после сохранения тела; повтор действий и stale
контексты отклоняются, EXPUNGE не добавлен. QA-кнопка «Тестовое входящее» действует
только в DEBUG synthetic режиме и изолированной схеме, без сетевого подключения.

Обновления окна объединяются в последовательный drain. События и их текущие
заголовки возвращаются одной транзакцией, включая письмо за пределами общей
страницы cache. Переход окна на передний план подавляет новые карточки, но не
отменяет действие уже показанной. Пока workspace занят, пользовательское действие
ждёт локально и повторно проверяет контекст перед исполнением. Это ожидание до
dispatch, а не повтор ранее отправленного MOVE. Отмена линеаризована с записью
команды на event loop: отменённая до записи команда не устанавливает pending
promise; после записи сохраняется фактический результат без разрешения повтора.

## Завершение согласованного объёма — 2026-10-15

В зашифрованном PostgreSQL сохранены подписи по аккаунтам, шаблоны ответа,
правила по отправителю/теме и локальные метки. Правила применяются только к новым
INBOX UID после первоначального baseline. Новые UID выбираются по возрастанию
страницами по 50; курсор не перескакивает через незагруженное поступление.
Один проход ограничен 1000 UID, оставшийся backlog продолжает следующий проход
без ожидания нового IDLE-события. Удалённые между SEARCH/FETCH UID учитываются
курсором. Приоритет Корзины выше Архива. Перед MOVE сохраняется полное тело.
Ошибка подготовки отдельного правила видна в исходящих, допускает явный повтор
подготовки/отмену и не блокирует другие правила или отправку по расписанию.

Отправка по расписанию сохраняет подготовленный черновик и время, выполняется
только при открытом приложении и подключённом аккаунте. Отмена возвращает письмо
в редактор без потери адресов, подписи и файлов. Допуск SMTP, правила MOVE и
расписания защищены транзакцией и отдельной сессией PostgreSQL с advisory lock.
Ручная отправка из другого окна не обходит допуск расписания; разрешение
расписания также проверяет владельцев связанных SMTP attempts. Второе окно/процесс
не может разрешить неизвестный исход, пока владелец ещё
выполняет операцию. После завершения владельца остаётся сохранённый receipt;
неизвестный исход допускает только явную проверку. Позднее завершение не может
переписать уже разрешённое состояние. Отмена/отключение во время SMTP AUTH
закрывает соединение и запрещает DATA; после возможной записи DATA исход остаётся
неизвестным и не разрешает автоматический повтор.

Изменение почтового адреса, IMAP/SMTP сервера, порта, защиты или пользователя
создаёт новый accountID. Repository и worker отказывают в повторном использовании
старой идентичности для другого источника: прежние UID, архив, правила и карточки
не направляются в новый ящик. Изменение только отображаемого имени сохраняет ID.

IDLE использует отдельное соединение для наблюдаемой папки, проверку CAPABILITY,
DONE и завершение tagged response, обновление сессии не реже 25 минут. Сервер без
IDLE использует 60-секундный опрос. Отключение закрывает рабочее и все наблюдающие
соединения, включая папку вне INBOX и ещё подключающийся watcher.

«Сохранённые версии…» открывает неизменяемые полные версии письма по 20 записей.
Длинный plain text читается страницами по 16000 символов без потери остатка;
HTML передаётся полностью в изолированный inert reader, без прежнего усечения
512000 символов. Лимит загрузки одного RFC822 остаётся 32 МБ. История не заменяет
текущее письмо и не подменяет исходные вложения.

Непрозрачные маршруты показанных уведомлений сохраняются зашифрованно (до 100).
После перезапуска они восстанавливаются без повторного показа старых баннеров.
Open может читать уже сохранённое письмо офлайн; Archive/Trash подключают явно
сохранённый аккаунт и повторно проверяют source generation, unread, privacy и
однократный допуск. Произвольный userInfo не задаёт аккаунт/UID. Явное отключение
аккаунта отзывает активацию. После доверенного восстановления маршрутов текущая
приватность также удаляет недопустимые старые системные карточки; до восстановления
они не очищаются преждевременно. Возрастной TTL не введён: действуют ограничение числа
маршрутов и актуальная проверка контекста.

Сборка включает переносимые libpq/OpenSSL/VoIP и notices. PostgreSQL libpq 18.6
собирается из закреплённого архива без GSSAPI/LDAP/server; OpenSSL 3.6.4 проверяется
по версии и лицензии. Нормальная TLS-проверка использует системное macOS SecTrust
с именем сервера; переменные SSL_CERT_FILE/DIR не подменяют корни доверия.
Явный CA допускается только отдельно переданным параметром синтетической проверки.
Каждая сборка пакуется в новую папку; проверенный подписанный результат заменяет
предыдущий bundle с восстановлением прежнего при ошибке публикации на диске.
`.references/` и Homebrew dylib paths не нужны запущенному приложению. PostgreSQL
и S3 остаются отдельными сервисами; они не встраиваются в приложение.

## Оставшиеся границы приёмки

Календарь и OAuth исключены пользователем. Реальные аккаунты, Keychain/provider
acceptance и обычный macOS баннер/звук/действия остаются на паузе. Синтетические
тесты не доказывают доставку/прочтение настоящей почты. Native QA и её ограничения
указаны в development-status. Developer ID/notarization и отдельный чистый Mac
не доступны в текущей среде; локальная подпись ad-hoc не доказывает распространение
через Gatekeeper. Переключение устройств Telegram-звонка остаётся ранее принятым
GAP; локальный код-пароль/автоблокировка исключены.
