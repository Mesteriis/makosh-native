## TelegramSwift

Официальный нативный macOS клиент, но существующая архитектура Cocoa/AppKit + TGUIKit, TelegramCore, Postbox, SwiftSignalKit, а не готовый независимый SwiftUI SDK. [AuthController / LoginAuthViewState](https://github.com/overtake/TelegramSwift/blob/579cebbf0c01fd41b712eff3647fa7f69db9665d/Telegram-Mac/AuthController.swift) задаёт phone/password/code и token authorization; [AccountContext](https://github.com/overtake/TelegramSwift/blob/579cebbf0c01fd41b712eff3647fa7f69db9665d/Telegram-Mac/AccountContext.swift) связывает account, сообщения, настройки и множество UI-сервисов; [ChatListController](https://github.com/overtake/TelegramSwift/blob/579cebbf0c01fd41b712eff3647fa7f69db9665d/Telegram-Mac/ChatListController.swift) показывает готовую модель списка диалогов. Перенос потребует отделить протокол/состояние от собственной UI-архитектуры.

Лицензия: README прямо говорит «version 2.0», LICENSE содержит GPL v2. Не найдено разрешение `or later` для приложения в целом. Консервативное решение для заимствования: **GPL-2.0-only**, пока upstream не подтвердит иное; сам шаблон в конце GPL не является однозначным grant для всего репозитория. [packages/EmojiSuggestions/Sources/emoji_suggestions.cpp](https://github.com/overtake/TelegramSwift/blob/579cebbf0c01fd41b712eff3647fa7f69db9665d/packages/EmojiSuggestions/Sources/emoji_suggestions.cpp) содержит отдельное «any later version» для компонента, что не расширяет лицензию всего приложения. Это оценка видимых notices, не окончательная юридическая классификация.

[INSTALL.md](https://github.com/overtake/TelegramSwift/blob/579cebbf0c01fd41b712eff3647fa7f69db9665d/INSTALL.md) требует recursive submodules, Homebrew C/C++ media toolchain, Xcode workspace и signing. Shallow clone без инициализации submodules не является build-ready. Для fork нужны собственный API ID/hash, bundle ID, branding; нельзя брать upstream credentials. Копирование GPL кода в предполагаемое MIT/закрытое ядро — отдельный лицензионный блокер.

## MMail

**MIT, наиболее конкретная функциональная база почты** из этих материалов: настоящие IMAP/SMTP, multi-account, cache, threading, sending, search. [actor IMAPSession](https://github.com/moerdowo/MMail/blob/69bf8c9b2436d7d000652f41362f8fdebf406599/MMail/Mail/IMAPSession.swift) держит подключение одного аккаунта и сериализует операции, но `run` повторяет любой сбой один раз — перенос неидемпотентных операций требует отдельного аудита. [SMTPService.authenticate](https://github.com/moerdowo/MMail/blob/69bf8c9b2436d7d000652f41362f8fdebf406599/MMail/Mail/SMTPService.swift) использует AUTH LOGIN. [Keychain](https://github.com/moerdowo/MMail/blob/69bf8c9b2436d7d000652f41362f8fdebf406599/MMail/Mail/Keychain.swift) хранит пароль в macOS Keychain; результаты SecItemAdd/Delete не проверяются, поэтому это референс, не готовый надёжный security layer.

[Account / Email](https://github.com/moerdowo/MMail/blob/69bf8c9b2436d7d000652f41362f8fdebf406599/MMail/Models/Models.swift), [AppModel](https://github.com/moerdowo/MMail/blob/69bf8c9b2436d7d000652f41362f8fdebf406599/MMail/State/AppModel.swift), [RootView](https://github.com/moerdowo/MMail/blob/69bf8c9b2436d7d000652f41362f8fdebf406599/MMail/Views/RootView.swift) подтверждают разделение models/network/state/SwiftUI, однако AppModel централизует широкий объём поведения. Aether следует оценивать отдельно как UX reference; факт наличия экрана не заменяет MMail transport/session implementation. Aether данным исследованием не проверен, его функциональность не приписывается ему.

[project.yml](https://github.com/moerdowo/MMail/blob/69bf8c9b2436d7d000652f41362f8fdebf406599/project.yml) задаёт macOS 14, Swift 5, XcodeGen, swift-nio >=2.64, nio-ssl >=2.24, nio-imap на точном commit. README требует Xcode 16+. OAuth Google/iCloud/Outlook не реализован: manual IMAP/SMTP/app passwords. Signing/notarization релизов не доказаны сборкой, README сообщает not notarized.

## WhatsApp Zen

MIT собственного кода, SwiftUI/AppKit UI + Rust protocol core. [Core.start / Core.call / Core.raw](https://github.com/mdenizay/whatsapp-zen/blob/790066aa411d395562a572101a74057147af67db/app/Sources/WhatsAppZen/Core.swift) → [C ABI](https://github.com/mdenizay/whatsapp-zen/blob/790066aa411d395562a572101a74057147af67db/app/Sources/CWACore/include/wacore.h) → [WAStart / WACall / WAFree](https://github.com/mdenizay/whatsapp-zen/blob/790066aa411d395562a572101a74057147af67db/zen/core/src/ffi.rs) — реальная граница: JSON request с cmd/account, JSON reply data/error, callback events. Swift копирует callback bytes до dispatch на main; результат WACall освобождает WAFree; blocking calls исполняет на concurrent queue. Rust staticlib + rlib, Tokio runtime, multi-account SQLite. Комментарии Swift «Go core» остались от прежнего backend; реальную Rust сборку подтверждает [build.sh](https://github.com/mdenizay/whatsapp-zen/blob/790066aa411d395562a572101a74057147af67db/build.sh), прочитанный, но не запущенный.

[Chat / Message models](https://github.com/mdenizay/whatsapp-zen/blob/790066aa411d395562a572101a74057147af67db/app/Sources/WhatsAppZen/Models.swift) и [MainView](https://github.com/mdenizay/whatsapp-zen/blob/790066aa411d395562a572101a74057147af67db/app/Sources/WhatsAppZen/MainView.swift) — референс chat UI/state. Авторизация: companion-device QR linking; OAuth/API продукта нет. README предупреждает о неофициальном протоколе и риске ограничения аккаунта, о plaintext сообщениях на диске, слабой проверке звонков.

[zen/core/Cargo.toml](https://github.com/mdenizay/whatsapp-zen/blob/790066aa411d395562a572101a74057147af67db/zen/core/Cargo.toml) закрепляет whatsapp-rust 0.7.0, rusqlite 0.39, VoIP/native crypto/media зависимости; [app/Package.swift](https://github.com/mdenizay/whatsapp-zen/blob/790066aa411d395562a572101a74057147af67db/app/Package.swift) требует macOS 26 и libwacore.a через unsafe linker flags. README: Apple silicon, Xcode 26+, Rust. build.sh сначала строит Rust staticlib и копирует её в legacy core/build. Старый optional Go backend на whatsmeow — MPL-2.0; Rust upstream описан MIT, транзитивные лицензии отдельно не аудированы. Подключение этого core требует контрактных тестов JSON/ABI и собственного хранения/авторизации.

## teams-cli

MIT Rust CLI/TUI, **имеет библиотечную поверхность**, а не только executable: [pub mod auth / graph / config / error](https://github.com/rvben/teams-cli/blob/9c8a72c32369f9d9bd15b793099522a80070a063/src/lib.rs). Однако это общий crate с CLI/TUI зависимостями, без Swift/C ABI; не plug-in для SwiftUI. [GraphClient / Page](https://github.com/rvben/teams-cli/blob/9c8a72c32369f9d9bd15b793099522a80070a063/src/graph.rs) реализует supported Microsoft Graph v1.0, chats/channels/messages/send, bounded pagination. Page.items — Vec<serde_json::Value>, поэтому описание «typed core» в README не означает fully typed domain messages.

[BASE_SCOPES / login / access_token](https://github.com/rvben/teams-cli/blob/9c8a72c32369f9d9bd15b793099522a80070a063/src/auth.rs) разделяет browser PKCE и device code, refresh хранится через OS keyring. ChannelMessage.Read.All отдельно и требует admin consent; Microsoft 365 work/school, tenant consent/Teams licensing остаются внешними блокерами. No delegated calling/screensharing, нет personal accounts и private Teams protocol. Не извлекать desktop tokens.

[Cargo.toml](https://github.com/rvben/teams-cli/blob/9c8a72c32369f9d9bd15b793099522a80070a063/Cargo.toml) требует Rust 1.90, edition 2024; tokio, reqwest/rustls, keyring, clap, ratatui/crossterm. Для macOS приложения: либо отдельный Rust adapter/FFI с контролем OAuth lifecycle, либо собственный Graph transport по изученному публичному контракту. Встраивание CLI subprocess допустимо как прототип, но не доказательство production bridge.
