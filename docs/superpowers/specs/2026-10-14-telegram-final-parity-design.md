# Telegram: завершение оставшегося переноса

Дата: 2026-10-14. Основание: «переключение устройств во время звонка; это не
делаем, пометь как геп а остальное все делаем одним проходом».

## Объём и ограничения

Одним непрерывным проходом закрываются автоматическая очистка облачного кэша,
постоянные ручные фоновые загрузки между чатами, оставшиеся варианты тем/обоев
и оформление личного звонка (видеоаватар, фон/декорации, волна, сигнал вызова,
представление ключа, положение своего видео, скрытие управления).

Native SwiftUI/AppKit, macOS26+, Apple Silicon. Общая боковая панель сохраняется.
Reference TelegramSwift579cebbf используется для сверки поведения; GPLv2-only UI,
ресурсы и credentials не копируются. Новые GPLv3 зависимости требуют pin/license
review и независимой подготовки без `.references/`. Собственный код MIT,
совмещённое приложение GPLv3. Приватное engine logging выключено.

Постоянные наблюдённые версии сообщений и S3 не удаляются очисткой кэша.
S3 OFF запрещает любые новые копии, включая фоновые загрузки/восстановление.
Идентичность и все asynchronous callbacks привязаны к аккаунту и поколению.
Тесты и UI используют изолированные synthetic данные. Реальный Telegram-аккаунт,
собеседник и разрешённые действия будут предоставлены пользователем в самом конце.
Чужие Keychain items и личные аккаунты не читаются.

**Принятый gap:** смена input/output/camera во время активного звонка.
Настройки устройств применяются только к следующему звонку. Локальный код-пароль
и автоблокировка остаются исключены. Групповые звонки/демонстрация экрана и другие
каналы связи не входят в этот проход.

## Безопасная очистка

Отдельная account-owned автоматическая служба читает реальные timestamps
MediaBox.resourceUsageWithInfo (mtime полного/частичного ресурса; неизвестное0
не трактуется как старое). Настройки срока хранения1/7/31дней/бессрочно и размера
5/16/32GB/без ограничения повторяют проверенные варианты StorageUsageController.
По умолчанию очистка выключена: бессрочно и без лимита. Изменение настройки
активирует потребителя без открытия окна настроек, затем проверка раз в15минут.

Удаляются только заново проверенные облачные ресурсы из существующего allowlist,
сначала просроченные, затем наиболее старые до лимита. Активные keepResource,
неизвестные/secret/local/неполные принадлежности, отправляемые оригиналы и
S3-подготовка защищены. Перед удалением повторяется inventory/resolve и permission
barrier; removal force:false, результат проверяется повторным scan. Изменившийся
состав не даёт удаления. Остаток защищённых данных не скрывается как успех лимита.
Фоновая служба не использует контекст окна ручного подтверждения.

## Ручные фоновые загрузки

Ручная full-загрузка принадлежит аккаунту, не выбранному чату/окну поиска.
Превью и автоматические загрузки сохраняют существующий visible/window barrier.
Менеджер показывает текущий аккаунт целиком; закрытие менеджера/выбор чата не
отменяет ручную загрузку. Лимит1000 записей и ограниченная concurrency защищают
память. Logout/rebind прекращает leases; устаревший transfer не отменяет другой.

В encrypted Postbox сохраняется только bounded metadata очереди: message ID,
attachment ID, manual intent и phase, bounded name/byteCount/photo для проверки
неизменности источника и отображения отказа. Ни cache paths, access hashes, ни bytes
не попадают в journal/PG. При запуске того же выбранного аккаунта native message
и resource reference перечитываются и сопоставляются; исчезнувший/изменённый
источник видимо отказывается, без угадывания. Завершённые записи восстанавливают
lease native cache. Cancel/retry/clear сохраняются атомарно/последовательно;
ошибка persistence видима и не выдаёт durable ACK. Новое поколение не принимает
старые callbacks. S3 capture сохраняет исходную identity и заново проверяет
актуальную политику чата; неизвестный чат не получает разрешение.
Уже работающая передача имеет60секундный таймер бездействия: только новый
конечный прогресс или рост полного zero-offset partial range продлевает срок.
Долгая передача с прогрессом продолжается; повторные/некорректные события не
держат зависшую передачу бесконечно. Старый timer не прерывает новое поколение.

Архивные копии не теряются при потоке завершений: ручная передача заранее
получает bounded reservation, фиксирует FD целого файла до первого await и
ожидает свежей PostgreSQL-политики/свободного места в очереди. Дополнительный
буфер ограничен8FD, прежние8прямых ручных и3автоматических слота сохраняются;
фоновая загрузка одновременно занимает не более4активных мест. S3 OFF не
шифрует/не ставит файл в spool и не ждёт ошибочных копий других чатов. Политика
ожидающих файлов перечитывается каждые5секунд, поэтому OFF снимает ожидание.
Перед фактической записью существующий repository повторно проверяет политику.
Целый файл можно открыть/экспортировать во время ожидания архива; отмена строки
не удаляет уже принятый архивом FD. Поздний callback не меняет новый аккаунт.

## Оформление

Существующие preferences читают прежние файлы. Цветные обои поддерживают1–4цвета,
rotation и узор с intensity; предпросмотр и применение используют одинаковый
собственный bounded renderer. Облачные PNG/WebP/SVG patterns нормализуются в
статический безопасный локальный файл: лимиты bytes/pixels/path complexity,
без внешних ссылок, scripts/entities/network. Неподдерживаемый или повреждённый
вход даёт явную ошибку без частичного применения. Палитра поддерживает alpha
основных уже потребляемых цветов и сохраняет её в фактическом UI.

Звонок сохраняет текущие позиции/действия референса. Видеоаватар muted, цикличный,
account-bound, прекращается при исчезновении представления/смене аккаунта;
Reduce Motion запрещает анимацию. Декоративные фон/волна создаются собственными
средствами без копирования GPLv2 assets. Сигнал вызова локально синтезируется,
останавливается при ответе/отмене/завершении, не открывает микрофон/камеру.
Ключ показывается совместимыми четырьмя emoji с точным verified algorithm/table
из допустимого GPLv3 источника; hex остаётся доступен для сравнения. Никакой
случайной/выдуманной emoji mapping. Preview перемещается по углам с bounds;
управление скрывается только в connected video при бездействии, возвращается
движением/клавиатурой, доступно VoiceOver и никогда не препятствует End/Escape.

## Проверка и приёмка

Каждая meaningful граница: RED→GREEN regression. Проверяются freshness, changed
inventory, unknown/future timestamp, active lease, restart/account change/stale
transfer, S3 OFF, malformed/hostile patterns, alpha persistence, call-state/audio
teardown, drag bounds и accessibility управления. Реальные PostgreSQL/S3,
scripts/dev-db.sh up, scripts/test.sh, scripts/build-app.sh и наблюдение actual
owned native UI обязательны. Затем одна independent whole-branch review и fixpass,
точный HEAD CI и интеграция. Hardware/Keychain acceptance отдельно фиксирует
фактически исполненные действия; synthetic результат не подменяет реальный.

Self-review: все ранее названные implementation gaps сопоставлены разделам;
переключение активных устройств явно исключено пользователем. Объём однозначен,
не требует нового visual direction или stage approval при указании «одним проходом».
