# Домен «ИИ»: основа, беседа и RAG — 2026-11-04

Статус: утверждён пользователем 2026-11-04 («Утверждаю»). Кода нет.

## Зачем

Пользователь хочет в общем рабочем пространстве Макоша отдельный домен «ИИ»
того же уровня, что почта, Telegram, WhatsApp, Teams и Телемост: свой пункт
боковой панели сервисов, свои настройки, свой сервисный модуль. Основной
сценарий — беседа с моделью о собственных данных: «найди все письма от
контакта», «переведи письмо», «составь досье по …». Поэтому в первый этап
сразу входит RAG по данным Макоша, а не только «пустой» чат.

Позже ИИ будет предоставлять возможности другим доменам (встраивание:
«перевести письмо» в самой почте и т. п.) и получит инструменты (tool calling).
Пользователь явно отложил это: сначала строится основа. Основа должна не
мешать этим этапам, но не реализует их.

## Цели первого этапа

1. **Модуль `MakoshAI`** рядом с `MakoshMail`/`MakoshTeams`/`MakoshTelemost`:
   свой worker на собственном исполнителе, своя PostgreSQL-схема с префиксом,
   Keychain-хранилище токенов, презентационные модели в
   `Sources/MakoshAI/Presentation/` с `package`-доступом (ADR-004).
   Пункт «ИИ» в боковой панели общего рабочего пространства.
2. **Подключения.** Пользователь добавляет одно или несколько подключений к
   OpenAI-совместимому API: название, базовый URL, токен (может быть пустым для
   локального сервера), необязательные заголовки организации/проекта.
   Токен — только в Keychain; в PostgreSQL, логах и экспорте его нет.
   Кнопка «Проверить» вызывает `GET /models` и показывает список моделей.
3. **Роли моделей.** В настройках домена для каждой роли выбирается
   подключение + модель (из списка `/models` или вручную):
   - **Беседа** — `POST /chat/completions`, потоковый ответ (SSE).
   - **Поиск (эмбеддинги)** — `POST /embeddings`, для RAG.
   - **Изображения** — генерация `POST /images/generations`.
   - **Распознавание речи** — `POST /audio/transcriptions`.
   - **Синтез речи** — `POST /audio/speech`.
   Роль может быть не назначена — соответствующая функция в UI недоступна с
   понятной подсказкой. Список ролей — расширяемое перечисление, а не
   универсальный «плагинный» фреймворк.
4. **Беседа.** Список бесед + окно беседы. Потоковый ответ, кнопка «Стоп»,
   «Перегенерировать» (старый вариант ответа сохраняется как версия, между
   версиями можно переключаться), редактирование своего сообщения с
   продолжением от него (новая ветка, старая сохраняется как версия).
   Использование ролей в беседе (решение автора дизайна):
   - микрофон — диктовка через роль «Распознавание речи», текст вставляется в
     поле ввода и не отправляется автоматически;
   - «Озвучить» у ответа — роль «Синтез речи», аудио не сохраняется в архив;
   - «Сгенерировать изображение» — отдельное действие в поле ввода; результат
     сохраняется как вложение беседы (см. «Хранение»).
   Вложения пользователя (картинки/файлы в запрос к модели) — вне первого этапа.
5. **RAG по данным Макоша.** Индексируются только данные, явно разрешённые
   флагами (см. «Приватность»): сообщения Telegram, WhatsApp, Teams, письма
   (тексты из постоянного архива), карточки контактов/досье. Каждый
   фрагмент хранит ссылку на источник: (service, accountID, conversationID,
   messageID) по `MessageArchiveIdentity`, либо идентификатор контакта.
   В беседе переключатель «Искать в моих данных» (по умолчанию включён, если
   назначена роль «Поиск»): при отправке выполняется векторный поиск,
   найденные фрагменты подмешиваются в запрос, а ответ показывает список
   источников; клик открывает оригинал в его домене.
6. **Беседы хранятся и удаляются.** В отличие от архива переписки, беседа с ИИ —
   собственный контент пользователя: её можно удалить целиком (с вложениями
   и версиями). Правило «никогда не удалять» архива сообщений на беседы ИИ
   не распространяется.

## Не цели (первый этап)

- Инструменты / tool calling, агентные действия, отправка чего-либо от имени
  пользователя.
- Встраивание ИИ в другие домены (кнопки в почте/чатах, автоответы, сводки).
- Вложения пользователя в запрос, мультимодальный ввод (vision).
- Голосовой разговор в реальном времени.
- Нестандартные API (Anthropic Messages, Gemini native) — только
  OpenAI-совместимый протокол; провайдеры, дающие совместимый эндпоинт,
  подключаются через него.
- Локальный запуск моделей внутри Макоша (локальный сервер вроде Ollama/LM
  Studio подключается как обычное подключение по URL).

## Анти-цели (провал, даже если «работает»)

- Любые данные почты/переписок/контактов ушли провайдеру без включённых
  флагов — включая фоновую индексацию, повторы, «прогрев» и отладку.
- Токен попал в PostgreSQL, логи, отчёты об ошибках, `docs/` или Git.
- Индексация или беседа блокирует MainActor или тормозит другие домены.
- Удаление/выключение источника не убирает его фрагменты из индекса.
- RAG-индекс подменяет или изменяет постоянный архив сообщений.

## Приватность: флаги «Доступно для ИИ»

Решения пользователя:

- Отдельный флаг на **чате**, на **контакте** и на **почтовом ящике**
  (аккаунте) — плюс, где применимо, на папке почты и аккаунте мессенджера.
- **По умолчанию выключено** на чатах, аккаунтах и почтовых ящиках.
- **Флаг контакта — три состояния** (решение пользователя 2026-11-04):
  «как у чата» (по умолчанию, контакт ничего не ограничивает), «разрешено»,
  «запрещено» (закрывает контакт везде).
- **Уровни ограничивают друг друга:** фрагмент допускается к индексации и к
  отправке модели, только если разрешены все применимые уровни. Пример:
  письмо от контакта X в ящике Y — только если включён ящик Y и контакт X не
  «запрещено». «Разрешено» на контакте не открывает выключенный чат/ящик.
- **Выключение флага удаляет уже проиндексированные фрагменты** этого
  источника из RAG-индекса. Архив сообщений не затрагивается.

Следствия для реализации:

- Флаги хранятся в PostgreSQL по образцу политики «Сохранять файлы в S3»
  (`archive_conversation_file_policy`): зашифрованно, по токену идентичности.
  Чат и аккаунт — в общем `MessageArchiveStore` (или соседней таблице того же
  хранилища); контакт — в хранилище контактов.
- Проверка политики выполняется дважды: при индексации и **при выдаче
  фрагмента в запрос** (флаг мог быть выключен после индексации, а удаление
  ещё не завершено).
- Сопоставление «сообщение → контакт» использует существующие идентичности
  досье (service, accountID, externalID). Если автора нельзя однозначно
  сопоставить с контактом, действует только флаг чата/ящика.
- Отправка в беседу собственного текста пользователя флагами не ограничена.
- Собственные исходящие сообщения пользователя флагом контакта не
  ограничиваются — только флагами чата/ящика (решение автора).
- Допуск проверяется по каждому сообщению: если в окне фрагмента есть
  сообщение запрещённого автора, исключается только оно, окно пересобирается
  без него (решение автора). Фрагмент хранит ссылки на все вошедшие сообщения
  и их авторов-контакты, чтобы выключение флага находило его.
- Индекс реагирует на ревизии контактов (связывание, слияние, отмена):
  изменение принадлежности идентичности пересчитывает допуск затронутых
  фрагментов — удаляет или ставит в очередь на догрузку (решение автора).
  Проверка при выдаче остаётся вторым рубежом.
- Флаги видны и переключаются из профиля чата, карточки контакта, настроек
  почтового ящика и общего экрана настроек ИИ (сводка «что доступно ИИ»).

## RAG: индексация

- **Источник:** общий зашифрованный журнал `MessageArchiveStore`
  (`archive_events`, монотонный `sequence`) — в него пишут Telegram, WhatsApp
  и Teams. Почта туда пишет только исходящие; полученные письма и их версии
  живут в собственных таблицах `MailRepository`. Поэтому (решение автора)
  в `MakoshCore` вводится узкий контракт «источник для ИИ-индекса»
  (курсор + пакет фрагментов текста с идентичностью); журнал архива — его
  первая реализация, почта реализует его поверх своих таблиц, а приложение
  связывает реализации с `MakoshAI`. `MakoshAI` не импортирует `MakoshMail`.
  Индексатор ведёт отдельный курсор на каждый источник.
- **Включение флага индексирует и прежнюю историю** этого чата/ящика/контакта
  (решение автора: иначе «найди все письма от контакта» не работает).
  Нужно состояние догрузки на поток и прогресс в настройках. Для каждой идентичности
  индексируется последняя версия текста; `deleted`/`removedFromSource` убирают
  фрагменты из индекса (архив при этом сохраняется). Контакты/досье — по
  ревизиям `ContactStore`.
- **Нарезка:** сообщения чатов группируются в окна соседних сообщений одного
  разговора (контекст важен для коротких реплик); письма — по телу с
  заголовками (тема, от, кому, дата), длинные письма делятся на части.
  Конкретные размеры окон — решение исполнителя, с тестами.
- **Эмбеддинги** считаются ролью «Поиск». Смена модели эмбеддингов делает
  индекс несовместимым: индекс помечается моделью и размерностью, при смене —
  полная переиндексация в фоне, старый индекс используется до готовности
  нового (или поиск отключается — решение исполнителя, но без смешивания).
- **Хранение индекса:** PostgreSQL + расширение **pgvector** (решение
  пользователя 2026-11-04, включая открытые векторы). Текст фрагментов хранится зашифрованно, как остальной архив;
  векторы — в открытом виде, иначе поиск в БД невозможен. Это осознанный
  компромисс: вектор не является текстом, но частично раскрывает смысл.
  Dev-образ `postgres:18.6` заменяется на образ с pgvector, закреплённый по
  digest; лицензия/notices pgvector (PostgreSQL License) добавляются в
  `THIRD_PARTY_NOTICES.md`.
- **pgvector обязателен для RAG, но не для Макоша:** если расширение
  недоступно, домен ИИ работает только как беседа с понятной ошибкой в
  настройках; остальные домены и запуск приложения не затрагиваются.
  Docker-PostgreSQL — среда разработки; модель поставки пользователям
  решается на этапе распространения (roadmap), там pgvector — требование.
- **Резервные копии (решение автора):** флаги «Доступно для ИИ» входят в
  резервную копию архива вместе с политикой S3. RAG-индекс в копию не входит
  и после восстановления строится заново. Беседы ИИ в первом этапе не входят
  в резервную копию архива сообщений (иначе удалённая беседа вернётся при
  восстановлении); их резервирование — отдельное решение позже.
- **Ход и ограничения:** индексация идёт в фоне на исполнителе `MakoshAI`,
  пакетами, с ограничением частоты запросов к провайдеру, с возобновлением
  после перезапуска по курсору. В настройках видны прогресс, ошибки и кнопка
  «Пауза». Сетевые ошибки — повтор с задержкой; 401 — индексация
  останавливается до исправления подключения.

## Хранение бесед

- Отдельные таблицы с префиксом (`ai_`), QA-схемы с префиксом `qa_ai_`.
- Тексты сообщений бесед, версии ответов и список источников —
  зашифрованно в PostgreSQL. Сгенерированные изображения — в
  зашифрованном S3 по общим правилам `docs/object-storage.md` (метаданные и
  ключ в PostgreSQL); политика S3 для бесед ИИ по умолчанию ON, при OFF —
  зашифрованная локальная папка.
- Удаление беседы удаляет её записи и локальные файлы изображений. Бакет S3
  запрещает `DeleteObject` (`docs/object-storage.md`), поэтому у каждого
  изображения свой случайный ключ, хранящийся только в зашифрованной записи
  сообщения: после удаления записи объект в S3 остаётся нечитаемым
  шифротекстом (уточнение при реализации 2026-11-04). Это единственное место в
  Макоше с пользовательским удалением истории; оно не затрагивает архив
  сообщений и RAG-индекс.
- Прерванный поток (стоп, сбой, закрытие окна) сохраняет полученную часть с
  пометкой «прервано»; автоматического повторного запроса нет.

## Архитектура

- `MakoshAI` зависит от `MakoshCore` и `CPostgres`; не импортирует модули
  других сервисов. Данные получает через общие контракты Core
  (`MessageArchiveStore`, хранилище контактов) — это и есть «общий
  источник», а не прямой доступ к Telegram/почте.
- Сетевой клиент OpenAI-совместимого API — собственный, на `URLSession`, без
  сторонних SDK. TLS — системный. Без логирования тел запросов/ответов.
- MainActor: только состояние UI, ввод, отображение потока. HTTP, SSE-разбор,
  эмбеддинги, SQL, шифрование — на исполнителях `MakoshAI`; публикация в UI
  после проверки поколения беседы/подключения (`docs/main-thread-boundaries.md`).
- Задел на встраивание и инструменты: worker предоставляет пакетный
  (`package`) асинхронный интерфейс «выполнить запрос к роли» и «найти
  фрагменты», не завязанный на UI беседы. Внешний для других модулей API
  сейчас не публикуется.

## Ограничения проекта, которые действуют здесь

- Нативный SwiftUI/AppKit, macOS 26+, Apple Silicon.
- Синтетические данные и изолированные схемы для тестов и UI-QA; никаких
  личных аккаунтов. Для HTTP — поддельный OpenAI-совместимый сервер в
  тестах. Реальный провайдер подключается только по явному разрешению
  пользователя, и без включения флагов на реальных данных.
- `scripts/dev-db.sh up`, `scripts/test.sh`, `scripts/build-app.sh`; запись
  итогов в `docs/development-status.md`; запись решений в `docs/architecture.md`.

## Оставлено исполнителю

- Точная раскладка файлов внутри `Sources/MakoshAI`, имена типов.
- Размеры фрагментов, top-k, порог релевантности, формат системного промпта
  с источниками.
- Индекс pgvector (HNSW/IVFFlat) и его параметры.
- Детали UI бесед в рамках общего рабочего пространства и визуального языка
  существующих доменов.
- Где именно в настройках почты/чатов размещаются переключатели флагов.

## Решения автора дизайна (не подтверждены пользователем отдельно)

- Контракт источника для индекса в Core; почта реализует его поверх своих таблиц.
- Включение флага догружает прежнюю историю.
- Свои исходящие не требуют флага контакта; запрещённый автор исключается
  из окна поштучно; индекс реагирует на ревизии контактов.
- Без pgvector домен ИИ работает только как беседа.
- Флаги — в резервной копии; индекс и беседы — нет.
- Голос: диктовка без автоотправки; озвучка без сохранения.
- Изображения: только генерация, результат — вложение беседы в S3.
- Вложения пользователя и vision — вне первого этапа.
- Только OpenAI-совместимый протокол.
