# Панель ИИ в чате и контекст беседы — 2026-11-05

Статус: на утверждение пользователя. Кода нет. Проверен свежим читателем (6 вопросов закрыты ниже). Первый из четырёх проектов,
согласованных 2026-11-05 (порядок ниже).

## Зачем

Пользователь хочет обсуждать с ИИ конкретную переписку там, где её читает:
«оцени диалог», «оцени стиль общения», «что он обещал на прошлой неделе».
Сейчас беседа ИИ живёт только в отдельном разделе «ИИ», а поиск по данным
опирается на индекс эмбеддингов, который не работает без ключа эмбеддингов на
прокси пользователя (`ai.sh-inc.ru`) и видит только архив Макоша. Индексация
поставлена пользователем на паузу. Этот проект работает без эмбеддингов: в
контекст модели беседы явно передаются выбранные сообщения и письма.

Встраивание ИИ в другие домены было отложено в дизайне домена ИИ
(`2026-11-04-ai-domain-design.md`); этот проект и есть тот этап.

## Порядок проектов (решение пользователя)

1. **Этот проект:** панель ИИ в чате, контекст через «+» и «@».
2. Загрузка истории за период с сервера сервиса и локальные эмбеддинги на Mac
   (общая основа поиска и детектора; снимает зависимость от ключа эмбеддингов).
3. Детектор противоречий: отдельный флаг чата, плашка во всю ширину ленты,
   «Принять новое» / «Не противоречие».
4. Метки отношений по периодам («друзья до 1 сентября, коллеги после»).

Проекты 2–4 здесь не проектируются; этот проект не должен им мешать.

## Цели

1. **Панель ИИ справа от открытой переписки** в Telegram (первым), затем в
   WhatsApp и почте. Открывается кнопкой в шапке чата, закрывается так же;
   ширина изменяемая, состояние открытия запоминается на сервис.
2. **Текущий чат — контекст по умолчанию.** При открытии панели к беседе
   прикреплена карточка открытого чата. По умолчанию в контекст идут
   **последние 200 сообщений**; на карточке переключатель периода:
   «последние 200», «за неделю», «за месяц», «с … по …». У письма в контекст
   всегда идёт само письмо целиком (тема, отправитель, дата, текст).
3. **«+» в поле ввода** открывает выбор источника: любой чат Telegram,
   WhatsApp, Teams, письмо, контакт/досье. Выбранное становится карточкой
   контекста с тем же переключателем периода (для чатов).
4. **«@» при наборе** показывает подсказки по названиям чатов, контактам и
   темам писем; выбор вставляет карточку контекста (как «+»).
5. **Карточки видны и снимаются.** Над полем ввода — ряд карточек: что именно
   уйдёт модели (название, сервис, период, число сообщений). Крестик убирает
   карточку. Без карточек вопрос уходит без контекста данных.
6. **Беседы хранятся в общем хранилище ИИ** (то же шифрование и версии), с
   привязкой к чату. Панель чата показывает только беседы этого чата
   (последняя открыта, список — выбором), раздел «ИИ» — все, с значком чата и
   фильтром «Все / Без привязки / По чатам»; клик по значку открывает чат.
   Из панели — кнопка «Открыть в разделе ИИ».
7. **Ответ показывает, на каких сообщениях он основан** — как источники RAG
   сейчас, с переходом к сообщению.

## Не цели

- Эмбеддинги, индекс, поиск по всем данным — проект 2. Переключатель
  «Искать в моих данных» в панели не показывается, пока индекс на паузе или не
  работает.
- Автоматические действия ИИ без вопроса пользователя (детектор — проект 3).
- Метки периодов — проект 4.
- Загрузка старой истории с сервера сервиса сверх того, что сервис уже держит
  локально, — проект 2 (здесь — только доступная локально история, см. ниже).
- Отправка ответов ИИ собеседнику, черновики ответа в поле ввода чата.
- Teams и Телемост как место размещения панели (как источник через «+»/«@» —
  да).

## Анти-цели (провал, даже если работает)

- Хоть одно сообщение или письмо уходит провайдеру без видимой карточки,
  которую пользователь мог снять.
- Контекст включает чат или письмо, которых пользователь не выбирал
  (кроме текущего чата при открытии панели — он виден карточкой).
- Сообщения запрещённого контакта («Запрещено» в досье) уходят провайдеру.
- Защищённый/секретный контент Telegram (секретные чаты, запрет пересылки)
  уходит провайдеру.
- Вызов ИИ блокирует главный поток или тормозит ленту.

## Приватность и доступ

- Явное прикрепление карточки (текущий чат при открытии панели, «+», «@») —
  согласие на отправку этих сообщений провайдеру беседы в этом вопросе. Флаг
  «Доступно для ИИ» управляет фоновой индексацией (проект 2) и не требуется для
  явной карточки (решение пользователя 2026-11-05: «не нужно»). Подпись
  переключателя «Доступно для ИИ» (`AIAccessBridge.swift`) уточняется: он
  открывает чат для фонового поиска и будущего детектора, а явная карточка в
  панели работает и без него.
- Флаг контакта «Запрещено» сильнее карточки. В группах сообщения такого
  автора исключаются, на карточке видно «скрыто N сообщений запрещённого
  контакта». Личный чат с запрещённым контактом и его досье не прикрепляются
  совсем — включая собственные сообщения пользователя в этом чате (карточка
  недоступна с пояснением). *(Решение автора дизайна.)*
- Секретные чаты Telegram не прикрепляются. Отдельные сообщения с запретом
  пересылки исключаются со счётчиком «скрыто N защищённых сообщений», как для
  запрещённого контакта; чат при этом прикрепляется. *(Решение автора дизайна.)*
- **Карточки принадлежат беседе, а не одному вопросу** *(решение автора
  дизайна)*: они остаются, пока пользователь их не снимет, и контекст по ним
  заново собирается и отправляется с каждым вопросом, чтобы уточнения («а что
  ещё?») работали. Лимит объёма считается как история беседы плюс карточки.
- Состав контекста фиксируется в каждом пользовательском сообщении беседы
  (какие карточки и период); текст источников в беседу не копируется. При
  повторной генерации контекст собирается заново по сохранённому составу.
- **Источники ответа — на уровне карточек** *(решение автора дизайна)*: под
  ответом список прикреплённых карточек (чат и период, письмо, контакт); клик
  открывает чат в начале периода, письмо или досье. Ссылки на отдельные
  сообщения, процитированные моделью, — позже. Поэтому новая ссылка на
  источник не требует `MessageArchiveIdentity`: карточка ссылается на сервис,
  аккаунт, чат и период (или письмо/контакт) своим типом.

## Откуда берутся сообщения

- Текущий и прикреплённые чаты: из локальной истории сервиса (Telegram —
  Postbox через движок; WhatsApp — его кэш; Teams — архив/кэш адаптера), а не
  только из архива Макоша, иначе переписка до появления архива недоступна.
  Если локально сообщений меньше выбранного периода, карточка показывает
  «доступно N сообщений, остальные не загружены» (загрузка с сервера —
  проект 2).
- Письма: из почтового хранилища (полная последняя версия текста).
- Контакт/досье: карточка контакта и заметки (без вложений).
- Сборка контекста — на исполнителях сервисов, не на главном потоке; на
  главный поток публикуется только готовый результат с проверкой
  аккаунта/чата/поколения (как в `docs/main-thread-boundaries.md`).

## Ограничение размера

- Каждая карточка сообщает примерный объём (символы → оценка токенов). Если
  общий объём превышает лимит модели беседы (настройка роли «Беседа», по
  умолчанию консервативно ~100 тыс. символов), отправка блокируется с
  подсказкой сузить период; молча ничего не обрезается.

## Что оставлено исполнителю

- Точная вёрстка панели и карточек в рамках существующего стиля
  (`WorkspaceStyle`, материалы правой колонки) и сверка с референсами в
  `docs/reference-interface.md`.
- Формат системного сообщения с контекстом (как сейчас в `AIRetrieval.context`).
- Хранение привязки беседы к чату в `AIConversation` (обратно совместимое
  поле) и способ фильтрации списка.
- Порядок подключения сервисов после Telegram.

## Объём поставки *(решение автора дизайна)*

- Панель — в Telegram. Панель в WhatsApp и почте — следующие шаги того же
  плана, после рабочей панели Telegram, на общей основе.
- Источники через «+»/«@» в первой поставке: чаты Telegram и WhatsApp, письма,
  контакты/досье. Teams как источник — следующий шаг (если у адаптера нет
  чтения локальной истории на его исполнителе, это отдельная задача плана).

## Проверка

- Синтетический QA-бандл ИИ (`run-ai-qa.py`, схема `qa_ai_`) с офлайн-
  провайдером: открытие панели в синтетическом чате, карточка текущего чата,
  «+», «@», снятие карточки, исключение запрещённого контакта, блок по объёму.
- Тесты: сборка контекста (период, запрещённый контакт, защищённый контент,
  лимит), сохранение привязки беседы, обратная совместимость старых бесед.
- Живая проверка на реальном чате — только по отдельному разрешению
  пользователя и с выбранным им чатом.
