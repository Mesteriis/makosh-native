# Файлы, часть 3: пересылка и карточка «файл» для ИИ — 2026-11-06

Статус: на утверждение пользователя. Кода нет. Проверен свежим читателем
(4 вопроса, все закрыты моими решениями ниже). Третья часть файлового
направления (часть 1 — раздел «Файлы» и Paperless, выполнена; часть 2 — SMB/S3,
отложена решением пользователя 2026-11-06).

## Зачем

Два случая пользователя 2026-11-06: переслать форму открытия автономо
(лежит в Paperless) собеседнику в чат; отдать договор (Paperless или письмо)
ИИ с вопросом «сколько мне будет стоить эта услуга по этому договору» или
«юридическая оценка». Сейчас файл из Paperless или архива можно только
сохранить на диск, а ИИ видит лишь чаты, письма и досье.

Попутно снимается ограничение, которое пользователь не утверждал: жёсткие
100 000 символов на историю и контекст беседы (`AIContextBuilder.defaultLimit`,
моё решение от 2026-11-05). Лимит становится настройкой модели.

## Цели

1. **Бюджет контекста от модели.** У роли «чат» в Настройках → ИИ поле
   «Контекст модели, токенов» (по умолчанию 128 000). Бюджет беседы —
   85 % от него (запас на ответ); символы оцениваются в токены по тексту:
   кириллица ≈ 2,5 символа на токен, остальное ≈ 4. Превышение — честный
   отказ с числами («контекст 96 000 токенов при бюджете 108 800 …»), как и
   сейчас, без молчаливой обрезки. Константа 100 000 удаляется; панель чата
   и все карточки живут по тому же бюджету.
2. **Карточка «файл»** в панели ИИ и разделе «ИИ». Источники: файл архива
   Макоша (запись каталога) и документ Paperless. Пути добавления: «+» и «@»
   (поиск по именам файлов каталога и по документам Paperless), контекстное
   меню файла везде, где он виден, — «Спросить ИИ…» открывает раздел «ИИ» с
   новой беседой и прикреплённой карточкой; из открытой беседы — «+».
3. **Текст файла извлекается на Mac.** PDF: текстовый слой (PDFKit) постранично;
   страницы без текста — распознавание Vision (русский, испанский, английский,
   точный режим). Картинки (JPG/PNG/HEIC/TIFF): Vision. Word/RTF/ODT/TXT/MD/CSV:
   `NSAttributedString`/UTF-8 (CP1251 как запасная кодировка). Для документа
   Paperless скачивается оригинал и разбирается так же; OCR-текст Paperless —
   только запасной вариант, когда локальный разбор дал меньше 50 символов на
   страницу (решение пользователя: распознавание Paperless плохо работает с
   русским и таблицами). Карточка помечает «распознано со скана», чтобы цифры
   из таблиц перепроверялись.
4. **Страницы на карточке.** Если файл не влезает в бюджет, карточка
   предлагает диапазон «страницы с … по …» (по умолчанию — ничего не
   отправляется, пока диапазон не выбран). Диапазон можно задать и заранее.
5. **Пересылка.** У файла в «Файлах», в архиве Paperless, у вложения письма,
   файла Telegram, сообщения WhatsApp и файла Teams — «Отправить в чат…» и
   «Отправить письмом…». Выбор адресата — поиск по чатам Telegram и WhatsApp
   и контактам с адресом почты (тот же ранжировщик, что у «+»). Файл попадает
   в составитель выбранного чата (как документ) или в новое письмо как
   вложение; отправляет пользователь сам, после проверки (его решение).
   Для Paperless берётся оригинал.
6. **«Из Файлов…» в составителях** Telegram («Прикрепить» → «Из Файлов…»),
   WhatsApp (меню вложения) и почты (рядом с «Прикрепить файл»): выбор из
   каталога и Paperless с поиском; дальше тот же путь, что у файла с диска.

## Не цели

- Отправка сразу, без составителя; пересылка в Teams; Teams как источник
  карточек (файлы Teams попадают к ИИ только через «Спросить ИИ…» у превью).
- Автоматическое чтение файлов ИИ (индекс, поиск по данным) — только явная
  карточка. Документы Paperless в индекс не попадают.
- Хранение извлечённого текста: он живёт в памяти процесса на время беседы и
  пересчитывается при перезапуске; на диск и в PostgreSQL не пишется.
- Извлечение из архивов (zip), таблиц Excel/Numbers, презентаций и видео —
  карточка честно отвечает «текст из этого типа файла не извлекается».
- Структурный разбор таблиц: Vision отдаёт строки, не ячейки.
- Изменение лимитов других ролей (эмбеддинги, изображения) — только роль «чат».

## Анти-цели

- Файл уходит на прокси ИИ только когда пользователь явно прикрепил карточку и
  отправил вопрос; «Спросить ИИ…» прикрепляет, но не отправляет.
- Никакой обрезки текста без ведома: либо весь выбранный диапазон, либо отказ.
- Временные копии (скачанный оригинал, страницы для OCR, файл для составителя)
  — в каталогах 0700/0600, удаляются после передачи или при закрытии;
  никаких копий в общих папках.
- Распознавание только на Mac (Vision), без облачных OCR.

## Ограничения

- Native SwiftUI/AppKit, macOS 26+, Swift 6; извлечение текста, OCR и
  скачивание — вне MainActor (актор в `MakoshFiles`).
- OCR ограничен 200 страницами на файл; дальше карточка сообщает «распознаны
  первые 200 страниц» и предлагает диапазон. Рендер страницы для OCR — 150 dpi.
- Один файл на карточку; карточек в беседе — сколько угодно в пределах бюджета.
- Бюджет считается по тексту системного хода (как сейчас) плюс история;
  оценка токенов — эвристика, не токенизатор модели; отказ прокси по длине
  всё равно показывается как ошибка модели.

## Как это устроено

### `MakoshAI`

- `AIRoleAssignment.contextTokens: Int?` (`decodeIfPresent`; nil → 128 000).
  `AITokenEstimate.tokens(in: String) -> Int` (кириллица 2,5, остальное 4).
  `AIContextBuilder.turn(_:historyCharacters:limit:)` → `turn(_:history:budgetTokens:)`,
  `AIFailure.contextTooLarge(tokens:budget:)`. Настройки: поле у роли «чат».
- `AIContextCard.file(source: AIFileSource, title: String, pages: ClosedRange<Int>?)`,
  `AIFileSource { case archive(recordID: UUID); case paperless(connectionID: UUID, documentID: Int); case staged(id: UUID) }`;
  `id` = `file:archive:<uuid>` / `file:paperless:<conn>:<doc>` / `file:staged:<uuid>`
  (диапазон не входит в id — как период у чата). `.staged` — закрытая копия
  в `FileHandoffStage` для файлов без записи архива (чат с выключенным S3,
  превью Teams, ещё не захваченное вложение): живёт до выхода из приложения;
  после перезапуска карточка показывает «копия недоступна — прикрепите
  заново» и в контекст не идёт.
- `AIContextMaterial.document: AIContextDocument?` —
  `{ pages: [String], pageCount: Int, selected: ClosedRange<Int>, paginated: Bool, recognized: Bool, truncatedOCR: Bool, source: String }`;
  строитель печатает `=== Файл «…» (страницы a–b из N, распознано со скана) ===`
  (для непагинированных — «части a–b из N») и `--- стр. k ---` / `--- часть k ---`
  перед каждой; для нескольких карточек — подряд, как сейчас.
- Предложения «+»/«@»: `AIContextSuggestion` с карточкой `.file`; подпись
  «Файл · Почта/Telegram/…» или «Paperless».

### `MakoshFiles`

- `FileTextExtractor` (actor): `extract(_ file: URL, name: String, pages: ClosedRange<Int>?) async throws -> ExtractedText`
  (`pages: [String]`, `pageCount`, `recognizedPages: Set<Int>`, `truncatedOCR`).
  Правила по категории (см. цель 3); неподдерживаемый тип —
  `FilesFailure.unsupportedText(kind)`. Кэш в памяти по (ключ источника,
  диапазон), сбрасывается при выходе.
- `FileHandoffStage`: закрытый каталог `Application Support/Makosh/FileHandoffStage/<uuid>/`
  (0700), файл 0600; `stage(_ handoff) async throws -> URL`; `release(url)`;
  очистка всего каталога при старте приложения.
- `PaperlessServing.document(id:) -> PaperlessDocumentDetail` (`content`,
  `originalFileName`, `pageCount?`) для запасного текста; скачивание — уже
  есть (`download(id:original:to:)`).
- `FileDestinationSearch`: кандидаты адресатов (чат Telegram, чат WhatsApp,
  контакт с почтой) с ранжированием `AIContextRanking`-подобным образом;
  `FilePickerSearch`: файлы каталога по имени + документы Paperless (запрос к
  API при ≥ 3 символах, не чаще раза в 400 мс, последний побеждает).

### Приложение

- `AIContextBridge.material(for: .file(...))`: архив → `FilesHost.export`;
  Paperless → скачать оригинал через модель раздела; `.staged` → файл стейджинга;
  затем `FileTextExtractor`; при `< 50` символов на страницу и источнике
  Paperless — `document(id:).content`. Диапазон применяется до OCR.
  Правила доступа те же, что у чатов и писем: файл из личного чата или письма
  контакта, закрытого для ИИ, не прикрепляется («контакт закрыт для ИИ»);
  защищённое содержимое Telegram (`CopyProtected`, секретные чаты) не получает
  ни «Спросить ИИ…», ни пересылки, ни «В Paperless…» — пункты скрыты.
- Извлечение запускается при прикреплении карточки (иначе нельзя показать
  «страницы a–b из N» и предложить диапазон до отправки) в собственной задаче,
  не блокируя превью других карточек; на карточке — «извлекается… k из N» и
  «Отменить»; отменённая карточка остаётся без текста и в контекст не идёт.
  Форматы без страниц (Word/RTF/TXT/MD/CSV, картинка, запасной текст
  Paperless) режутся на части по ~3 000 символов на границах абзацев; меню
  диапазона и печать используют слово «часть», не «страница».
- `AIContextCardsView`: карточка файла показывает `страницы a–b из N`,
  «распознано со скана», меню диапазона (как меню периода у чата); при отказе
  по бюджету — подсказка «выберите страницы».
- `AIContextSearch` получает `files: FilePickerSearch`; `WorkspaceView.openAICard(.file)`
  открывает раздел «Файлы» на нужной строке (архив) или хранилище (Paperless).
- `FileSendMenu` → `FileActionsMenu`: «Отправить в Paperless…», «Отправить в
  чат…», «Отправить письмом…», «Спросить ИИ…». Запросы идут в `FilesHost`
  (`pendingSend`, `pendingForward`, `pendingAsk`), листы — в `WorkspaceView`.
- `FileForwardSheet`: поиск адресата → стейджинг → Telegram:
  `telegram.selectedChatID = id` и `model.prepareUpload(sources: [.init(source:, mode: .file)], …)`;
  WhatsApp: `whatsapp.selectChat(id)` → `composer.attach([url], asFiles: true, …)`;
  почта: `mail.compose()` с предзаполненным вложением
  (`MailWorkspaceModel.composerAttachments`, которые `MailComposeSheet` берёт
  при открытии) и адресом контакта.
- «Спросить ИИ…»: `destination = .ai`, `ai.workspace.newConversation()`,
  `ai.workspace.add(card)`; беседа не отправляется.
- «Из Файлов…»: `FilePickerSheet` (каталог + Paperless) → стейджинг → тот же
  путь, что у выбранного с диска файла, в каждом составителе.

### Экраны

```
Карточка в панели ИИ:  📄 Договор аренды.pdf · страницы 1–12 из 38 · распознано со скана ▾

Меню файла: Посмотреть · Сохранить как… · Открыть источник · ─ · Отправить в Paperless… · Отправить в чат… · Отправить письмом… · Спросить ИИ…
```

### Проверки

- `MakoshAITests`: оценка токенов (кириллица/латиница), бюджет от роли,
  карточка `.file` (id, Codable, совместимость старых бесед), печать документа
  в системном ходе, отказ с числами.
- `MakoshFilesTests`: извлечение из PDF с текстовым слоем (фикстура создаётся
  PDFKit в тесте), из картинки с напечатанным текстом (Vision; тест помечается
  медленным), из DOCX/RTF (`NSAttributedString`), TXT в CP1251; страницы без
  текста уходят в OCR; лимит 200 страниц; неподдерживаемый тип; диапазон;
  стейджинг (права, очистка при старте); поиск адресатов и файлов (ранжирование,
  задержка запроса к Paperless, поздний результат отбрасывается).
- `MakoshMailTests`: составитель открывается с предзаполненным вложением.
- Синтетический QA: окно «Файлы» получает «Спросить ИИ…» с подставной беседой?
  Нет — ИИ в QA «Файлов» не стартует; проверяется в QA ИИ (`qa_ai_`) с
  подставным файлом; пересылка — в синтетических окнах Telegram/WhatsApp/почты
  по одному файлу. Живая проверка — по команде пользователя: договор из
  Paperless в беседу ИИ и форма автономо в выбранный чат.
- Документация: `docs/files.md`, `docs/architecture.md` (ADR), `docs/reference-interface.md`,
  `docs/development-status.md`; план проекта 1 панели ИИ помечается: лимит
  заменён бюджетом модели.

## Решения, принятые за пользователя (проверить при чтении)

- Бюджет 85 % контекста модели; по умолчанию 128 000 токенов у роли «чат».
- Оценка токенов — эвристика по алфавиту, без токенизатора модели.
- Порог запасного текста Paperless — меньше 50 символов на страницу.
- OCR до 200 страниц, 150 dpi, языки ru/es/en.
- Извлечённый текст не сохраняется на диск.
- Пересылка открывает составитель; для WhatsApp и Telegram файл идёт как
  документ (не фото), для письма — как вложение с адресом контакта.
- Teams — только источник через «Спросить ИИ…» у превью, не адресат.
- Файлы без записи архива идут к ИИ через непостоянный источник `.staged`
  (живёт до выхода), а не через принудительный захват в архив.
- Правила доступа ИИ и защита контента Telegram распространяются на файловые
  карточки и пересылку так же, как на чаты и письма.
- Извлечение текста — при прикреплении, с ходом выполнения и отменой.
- Непагинированный текст делится на части по ~3 000 символов.

## Что остаётся строителю

- Точные параметры `VNRecognizeTextRequest` (уровень, коррекция языка).
- Как отличить «страница без текста» от «страница с подписью» (порог символов).
- Разметка меню диапазона страниц и подсказки на карточке.
- Задержка и отмена запросов к Paperless при наборе в «+».
