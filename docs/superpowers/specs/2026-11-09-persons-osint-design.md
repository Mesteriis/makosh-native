# Раздел «Персоны»: OSINT-модуль на внешнем сервере flowsint — 2026-11-09

Статус: на утверждение пользователя. Кода нет. Пометка «моё решение» означает
выбор автора документа, который пользователь не обсуждал; его можно поправить
при чтении. Продолжение раздела «Персоны» (`2026-11-08-persons-design.md`) по
образцу разделов «Задачи», «Календарь» и «Персоны».

## Зачем

Досье персоны наполняется тем, что прошло через Makosh: книги, переписка,
письма. Снаружи о человеке или организации известно больше: аккаунты в
соцсетях под тем же username, публичный аватар, утечки, в которых засветился
адрес, оператор и страна телефона, домены, зарегистрированные на организацию.
Собирать это вручную по десяти сайтам долго, а складывать в заметки — значит
терять провенанс.

Открытый инструмент [flowsint](https://github.com/reconurge/flowsint)
(Apache-2.0) умеет это как граф: сущности (человек, почта, телефон, username,
соцаккаунт, домен, утечка) и «обогатители», которые по узлу одного типа
создают соседние узлы. Цель работы — чтобы выбранная персона в Makosh могла
пройти через flowsint, а найденное легло в её досье как **предложенные**
наблюдения с источником и ссылкой на задачу, которые пользователь принимает
или отклоняет. flowsint при этом остаётся отдельным сервером, который Makosh
сам ставит и обновляет по SSH из своего интерфейса.

## Решения пользователя (2026-11-09)

- **Вариант 2: отдельный сервер**, а не переписывание на Swift. Переписывать
  flowsint целиком бессмысленно: ценность в графе Neo4j, веб-интерфейсе и
  контейнерных инструментах (Maigret, Sherlock), которые Swift не нужны и в
  приложение не переносятся. Порт только HTTP-адаптеров дал бы тонкий
  результат ценой тех же правовых рисков внутри приложения.
- **Площадка — LXC 164 `flowsint` на PVE Spain** (`10.34.10.64`, Debian 13.6,
  Docker CE, sshd с паролем, пользователь `makosh` в группе `docker`,
  `/opt/flowsint`). Создан 09.11.2026; **сам flowsint в гостя не ставился** —
  установку и обновление делает Makosh из своего интерфейса. **Это важно:**
  установка с экрана Makosh — часть первого этапа, не отложенная работа.
- **Согласие.** Обогащение выключено по умолчанию. В карточке кнопка
  «Обогатить (OSINT)…» с диалогом: какие обогатители запустятся и какие
  данные уйдут на сервер. У книг-источников адресной книги отдельный флажок
  «обогащать автоматически» (выключен). Отправители писем, спам и скрытые
  персоны сами не обогащаются никогда.
- **Обогатители первого этапа.** Почта: Gravatar, HudsonRock, HIBP при
  наличии ключа. Телефон: страна и оператор, Veriphone при ключе. Username:
  Maigret. Имя: кандидаты username. Организация: домены через Whoxy при
  ключе. Исключены LinkedIn-скрейпинг, SIRENE, DeHashed, новости. Набор
  настраивается.
- **Результаты в досье** — только как «предложено» с провенансом
  `osint/<обогатитель>/<id задачи>`: соцаккаунты, утечки, аватар, оператор
  телефона, домены. Пользователь принимает или отклоняет каждое. Автослияние
  персон по OSINT-данным не работает.
- **Доступ к серверу — один SSH-туннель** через `swift-nio-ssh`: и
  установщик, и API flowsint (`127.0.0.1:5173` гостя) идут через него. HTTP
  наружу не открывается. Одна учётка в Keychain.
- **Скетчи.** Одно расследование «Makosh», по скетчу на персону. Удаление
  персоны и «Удалить везде» ставят журналируемую попытку удаления скетча.
  Ссылка на граф персоны открывается в браузере.
- **Установщик** проверяет Docker, клонирует закреплённый релиз из
  `Dependencies/Flowsint.lock.json`, пишет `.env` с секретами,
  сгенерированными на Маке и сохранёнными в Keychain, поднимает compose,
  ждёт health, регистрирует служебного пользователя. Обновление: смена пина
  и `compose pull`. Каждая внешняя запись журналируется, `unknown`
  закрывается чтением.
- **Ключи сторонних API** вводятся в Makosh, хранятся в Keychain и
  отправляются в хранилище flowsint.
- **Модуль `MakoshOSINT`** (SSH, клиент API, установщик, отображение графа в
  наблюдения) зависит только от `MakoshCore`; `MakoshPersons` узнаёт о
  результатах через узкий протокол, как от каналов; связывает их
  `PersonsHost`.
- **QA**: фальшивый flowsint в памяти и встроенный SSH-сервер-фикстура со
  сценарием команд, схема `qa_persons_`.

## Что известно о flowsint (разведка архива 09.11.2026)

Версия 1.2.11/1.2.12; Python 3.12 (uv-workspace из `flowsint-types`,
`flowsint-enrichers`, `flowsint-core`, `flowsint-api`), FastAPI, Celery с
Redis, PostgreSQL 15 (учётки, скетчи, журнал, ключи), Neo4j 5 с APOC (граф),
React за nginx. CLI-инструменты (maigret, sherlock, subfinder, dnsx, naabu)
запускаются контейнерами через `/var/run/docker.sock` сервиса `api`/`celery`.
Рабочий запуск — `docker compose -f docker-compose.prod.yml up -d` с `.env`
(`AUTH_SECRET`, `MASTER_VAULT_KEY_V1`, `NEO4J_PASSWORD`, `POSTGRES_PASSWORD`,
`FLOWSINT_VERSION`); образы `ghcr.io/reconurge/flowsint-api` и
`flowsint-app`; миграции Alembic выполняет `entrypoint.sh` сервиса `api`.
Наружу только порт `5173` (nginx: статика и прокси `/api/` → api); PostgreSQL,
Redis, Neo4j и api привязаны к `127.0.0.1` гостя. nginx отвечает 403 на любой
`Host`, кроме `localhost`, `127.0.0.1` и `[::1]` (защита от DNS rebinding);
через SSH-туннель Makosh обращается к `127.0.0.1:<порт>`, поэтому allowlist
править не нужно.

API (JWT bearer): `POST /api/auth/register {email, password}`,
`POST /api/auth/token` (form `username`/`password`) → `access_token`;
`POST /api/investigations/create`, `POST /api/sketches/create {title,
description, investigation_id}`, `GET /api/sketches/{id}/graph` (узлы
`{id, nodeType, nodeLabel, nodeProperties, …}` и рёбра `{source, target,
label}`), `POST /api/sketches/{id}/nodes/add` (GraphNode), `DELETE
/api/sketches/{id}` , `GET /api/enrichers`, `POST /api/enrichers/{name}/launch
{node_ids, sketch_id, params}` → `{id}` задачи Celery, `GET /api/scans/{id}`
→ `status` `PENDING|RUNNING|COMPLETED|FAILED`, `GET /api/keys` (имена без
значений), `POST /api/keys/create {name, key}`, `DELETE /api/keys/{id}`.
Идентификаторы узлов — `elementId` Neo4j; узел определяется типом и
первичным полем (`Email.email`, `Phone.number`, `Username.value`,
`Individual.full_name`, `Organization.name`, `SocialAccount.id`,
`Breach.name`, `Gravatar.hash`, `Domain.domain`).

Имена обогатителей первого этапа: `email_to_gravatar`,
`email_to_device_hudsonrock`, `email_to_breaches` (`HIBP_API_KEY`),
`phone_to_infos`, `phone_to_carrier` (`VERIPHONE_API_KEY`),
`username_to_socials_maigret`, `individual_to_username_candidates`,
`org_to_domains` (`WHOXY_API_KEY`). Ключи обогатитель берёт из хранилища
flowsint по имени параметра.

Лицензия Apache-2.0 с 25.01.2026 (ранее AGPL-3.0, релицензировано с согласия
авторов; NOTICE). Код flowsint в Makosh не копируется и не линкуется:
сервер — внешняя система, как Jira и Paperless.

## Цели

- Из карточки персоны одной командой запустить выбранные обогатители на её
  адресах, телефонах, username и имени; через минуты увидеть в карточке
  предложенные находки с источником и ссылкой на граф.
- Принять или отклонить каждую находку; принятые адреса, телефоны и username
  становятся значениями досье, остальное (соцаккаунты, утечки, аватар,
  оператор, домены) остаётся подтверждёнными наблюдениями раздела «OSINT».
- Для книг-источников адресной книги включить автоматическое обогащение
  новых персон (по желанию, выключено по умолчанию).
- Из Настроек → Персоны: ввести адрес, порт, логин и пароль SSH, проверить
  соединение, развернуть или обновить flowsint до закреплённой версии,
  видеть состояние (установленная версия, health, открытые попытки),
  вводить ключи сторонних API, открыть веб-интерфейс графа в браузере.
- Каждая внешняя запись (создание скетча, добавление узла, запуск
  обогатителя, ключ, удаление скетча, шаги установки) — одна журналируемая
  попытка; `unknown` закрывается чтением, не повтором.
- Синтетический QA показывает обогащённое досье без сервера и без сети.

## Не цели (в эту работу не входят)

- Перенос обогатителей или графа flowsint в Swift; работа без сервера.
- Установка Docker на сервер и подготовка гостя (сделано отдельно; у LXC 164
  остаются пробелы ввода по регламенту инфраструктуры: Wazuh/ClamAV, ключ
  пульта, PBS — это задачи инфраструктуры, не Makosh).
- HTTPS и публикация flowsint в сеть; доступ по ключу SSH (пароль — первый
  этап; ключ — следующая очередь).
- Обогатители доменов, IP, криптокошельков, сайтов; LinkedIn, SIRENE,
  DeHashed, новости; шаблонные обогатители (YAML) и flows flowsint.
- Автоматическое повторное обогащение по расписанию; обогащение
  отправителей писем, собеседников чатов (не книг), спама, скрытых.
- Чат с ИИ flowsint, его «анализы», совместная работа, роли.
- Перенос найденного в внешние адресные книги: признак «адресная книга»
  уносит только текущие значения досье; принятый из OSINT адрес уйдёт
  наружу как любое другое текущее значение — это не новое правило.

## Анти-цели (провал, даже если всё «работает»)

- Персональные данные ушли на сервер или в сторонний API без явного
  действия пользователя или без включённого им флажка книги.
- Находка OSINT стала текущим значением досье без подтверждения, или две
  персоны склеились из-за предложенного адреса.
- Пароль SSH, служебный пароль flowsint, значения `.env` или ключи API
  попали в PostgreSQL, журнал попыток, логи, Git или на экран (кроме кнопки
  «Скопировать пароль веб-интерфейса», см. ниже).
- Повторный запуск установщика сломал работающую установку: перезаписал
  `.env`, снёс данные, сменил версию без запроса.
- `unknown` разрешился повторной отправкой: второй скетч на персону, второй
  запуск того же обогатителя, второй ключ с тем же именем.
- Неизвестный хост-ключ SSH принят молча; смена хост-ключа не остановила
  соединение.
- Работа установщика или обогащения на MainActor; окно замерло на `compose
  pull`.

## Ограничения проекта

- Правила `AGENTS.md`: `MakoshPersons` не импортирует модули каналов и не
  импортирует `MakoshOSINT`; наблюдения append-only с провенансом; ошибки
  несут коды и стадии, никогда тел ответов, URL с токенами, адресов и
  телефонов; живой сервер — только по команде пользователя.
- Секреты только в Keychain (`org.makosh.osint.v1`): пароль SSH, пароль
  служебного пользователя flowsint, резервная копия секретов `.env`
  (`AUTH_SECRET`, `MASTER_VAULT_KEY_V1`, `NEO4J_PASSWORD`,
  `POSTGRES_PASSWORD`), ключи сторонних API. В PostgreSQL — только
  несекретные настройки и журнал.
- Внешняя зависимость `swift-nio-ssh` (Apache-2.0, Apple) закрепляется
  ревизией в `Package.swift`, как остальные пакеты Apple, с записью в
  `THIRD_PARTY_NOTICES.md`; совместимость с уже закреплённой ревизией
  `swift-nio` проверяется при реализации.
- flowsint закрепляется в `Dependencies/Flowsint.lock.json`: репозиторий,
  тег релиза, SHA коммита, digest образов `flowsint-api` и `flowsint-app`.
  Установщик ставит ровно этот коммит и эти digest (override-файл compose с
  `image: …@sha256:…`); расхождение — отказ, не предупреждение (моё
  решение). Обновление — смена пина в репозитории Makosh.
- Юридическая рамка: ETHICS/DISCLAIMER flowsint и условия HIBP, Veriphone,
  Whoxy, HudsonRock, Gravatar лежат на пользователе; Makosh показывает это в
  диалоге согласия и в Настройках один раз, без моральных лекций.
- Сборка и тесты не требуют сервера, сети и `.references/`.

## Модель

### Установка (`FlowsintInstaller`)

Установка — журналируемая операция `OSINTInstall` с шагами. Каждый шаг
сначала читает состояние и пропускает себя, если оно уже нужное
(идемпотентность); при сбое останавливается, запись шага получает код и
стадию. Повторный запуск продолжает с первого ненужного шага.

| Шаг | Проверка | Действие | Отказ |
| --- | --- | --- | --- |
| `connect` | хост-ключ совпадает с сохранённым | SSH с паролем; при первом подключении показать отпечаток и спросить подтверждение | `hostKeyMismatch`, `sshAuthFailed`, `sshUnreachable` |
| `docker` | `docker version`, `docker compose version` отвечают | — | `dockerMissing` |
| `checkout` | `git -C /opt/flowsint rev-parse HEAD` = SHA пина | clone `--branch <тег> --depth 1` или `fetch --tags && checkout <SHA>` | `installFailed("checkout")` |
| `env` | `/opt/flowsint/.env` существует | сгенерировать секреты на Маке → Keychain → записать файл `0600` через stdin exec-канала (`install -m 600 /dev/stdin …`); `FLOWSINT_VERSION=<тег>` | `installFailed("env")` |
| `override` | `docker-compose.makosh.yml` совпадает с пином | записать override с digest образов | `installFailed("override")` |
| `pull` | образы с нужными digest уже есть | `docker compose … pull` (до 15 минут, вывод потоком в журнал без секретов) | `installFailed("pull")` |
| `up` | все сервисы `running`/`healthy` | `docker compose … up -d`; ждать health api до 5 минут | `healthTimeout` |
| `register` | служебный пользователь входит | `POST /api/auth/register` (`makosh@flowsint.local`, пароль из Keychain); «уже есть» → вход | `apiRejected` |
| `investigation` | id расследования «Makosh» сохранён и читается | `POST /api/investigations/create` | `apiRejected` |
| `record` | — | записать версию, SHA и время в настройки | — |

Существующий `.env` никогда не перезаписывается; если его секретов нет в
Keychain (установка не из этого Makosh), установщик продолжает без них и
помечает «резервная копия секретов недоступна». Обновление — тот же
установщик с новым пином: `checkout`, `override`, `pull`, `up`; перед ним
Makosh показывает «сделайте снимок гостя» — снимки Proxmox вне досягаемости
Makosh. Удаление установки Makosh не делает (моё решение): это команда
владельца на PVE.

### Соединение (`OSINTSSHSession`, `OSINTTunnel`)

Один актор держит SSH-сессию `swift-nio-ssh` (аутентификация паролем,
проверка хост-ключа по сохранённому отпечатку; первый отпечаток
подтверждает пользователь). Exec-каналы — для установщика; канал
`direct-tcpip` на `127.0.0.1:5173` гостя — для API: локальный слушатель на
`127.0.0.1:<случайный порт>` живёт, пока открыта сессия, `URLSession`
ходит на `http://127.0.0.1:<порт>/api/…`. Обрыв сессии переводит
незавершённые попытки в `unknown`; следующая операция переподключается.
Ничего не слушает вне loopback; переадресация обратная (с сервера) не
открывается.

### Запуск обогащения (`OSINTRun`)

Запуск — одна строка `persons_osint_runs` на (персона, повод): повод
`manual` (кнопка) или `book:<id>` (флажок книги). Состояния `queued →
running → completed | failed | unknown`. Один раннер выполняет запуски
последовательно (очередь, моё решение: автоматические не обгоняют ручной).

Входные данные берутся из **текущих** значений досье на момент запуска
(не из предложенных и не из прежних): адреса, телефоны, username,
отображаемое имя (для `Individual`) или название организации. Ничего
другого (заметки, метки, должность, организация человека) на сервер не
уходит. Пользователь в диалоге может снять галочку с отдельного значения.

Шаги запуска, каждый — попытка (`persons_osint_attempts`):

1. `createSketch` — если у персоны нет скетча: `POST /api/sketches/create`
   с `title = <UUID персоны>`, `description = "Makosh"`; результат — в
   `persons_osint_sketches`. `unknown` → чтение списка скетчей расследования
   и поиск по `title`.
2. `addNode` на каждое значение: `Email{email}`, `Phone{number}`,
   `Username{value}`, `Individual{full_name}` или `Organization{name}`.
   `unknown` → чтение графа скетча и поиск узла по типу и первичному полю.
   Узел, уже существующий в графе, не создаётся второй раз (сервер сам
   сливает по первичному полю; Makosh всё равно сначала читает граф).
3. `launch` на каждую пару (узел, обогатитель из выбранного набора,
   совместимый по типу): `POST /api/enrichers/<имя>/launch` → id задачи.
   Опрос `GET /api/scans/<id>` каждые 3 секунды до `COMPLETED`/`FAILED`,
   не дольше 10 минут (Maigret — долгий), потом `unknown`. `unknown` →
   чтение графа: появились соседи ожидаемого типа у входного узла →
   `confirmed`; нет → остаётся `unknown`, пользователь решает «Проверить»
   (ещё одно чтение) или «Отказаться». Повторный `launch` — только явной
   командой.
4. `readGraph` — одно чтение `GET /api/sketches/<id>/graph` после всех
   задач; отображение в наблюдения (ниже). Чтение не журналируется как
   запись, но его отказ — `failed` запуска с кодом.

Ограничения: не больше одного запуска одновременно; не больше 200 новых
наблюдений за запуск (остальное — пометка «обрезано», моё решение); тело
графа до 10 МБ.

### Отображение графа в досье (`OSINTGraphMapping`)

Чистая функция: граф скетча + входные узлы запуска → список наблюдений.
Берутся только узлы, достижимые ребром от входного узла этой персоны
(соседи), чтобы чужие остатки скетча не попали в досье.

| Узел flowsint | Поле наблюдения | Значение | Принятие |
| --- | --- | --- | --- |
| `Email` | `emails` | адрес в нижнем регистре | становится значением списка |
| `Phone` (новый) | `phones` | номер в нормализованном виде | становится значением списка |
| `Phone` (входной, с `carrier`/`country`/`line_type`) | `phone.info` | `«+7… — Россия, МТС, mobile»` | остаётся наблюдением |
| `Username` | `usernames` | `value` | становится значением списка |
| `SocialAccount` | `social.<platform>` | `profile_url` (или `platform:username`) | остаётся наблюдением |
| `Gravatar` (`exists`) | `avatar` | `src` | остаётся наблюдением |
| `Breach` | `breach` | `«<title или name>, <breachdate>»` | остаётся наблюдением |
| `Device` (HudsonRock) | `leak.device` | `«<os>, <last_seen>»` без идентификаторов | остаётся наблюдением |
| `Domain` | `domain` | `domain` | остаётся наблюдением |
| `Organization` | `organization.suggested` | `name` | остаётся наблюдением; членство не создаётся само |

Каждое наблюдение: `Observation(field, value, source: SourceStamp(identity:
ServiceIdentity(service: "osint", accountID: <id сервера>, externalID:
"<id скетча>/<имя обогатителя>/<id задачи>"), fetchedAt), status: .proposed)`.
Identity персоны `osint/<сервер>/<скетч>` добавляется один раз при создании
скетча. Наблюдение, равное уже текущему значению или уже предложенному,
второй раз не добавляется; равное прежнему (`former`) — добавляется как
`proposed`, но в карточке помечено «ранее убрано».

Статус `rejected` добавляется в `ObservationStatus` (`MakoshCore`; старые
строки читаются как раньше, моё решение). Отклонённое скрыто и при
повторном появлении той же пары (поле, значение) от OSINT не предлагается
снова. Принятие адреса, телефона или username делает его **ручным значением**
списка (действие пользователя) и переводит наблюдение в `confirmed`; если
точное нормализованное значение уже есть у другой персоны, Makosh **не
склеивает** их сам, а показывает «совпадает с персоной X» и предлагает
«Склеить с…» (моё решение: автосклейка коллектора по OSINT-данным не
срабатывает, потому что принятие идёт не через коллектор). Остальные поля
при принятии становятся `confirmed` и показываются в разделе «OSINT»
карточки постоянно.

### Согласие и автоматический режим

- Глобальный переключатель «OSINT-модуль включён» в Настройках (выключен).
  Без него кнопка в карточке неактивна с подсказкой.
- Ручной запуск: диалог перечисляет обогатители (с пометкой «нужен ключ»
  у недоступных), значения, которые уйдут, сторонние сервисы, к которым
  обратится сервер, и строку о ответственности; кнопка «Запустить».
- `PersonBook.enrichAutomatically` (новое поле, по умолчанию `false`) —
  только у книг с `isBook` (CardDAV, Google, macOS, контакты Telegram,
  синтетическая). После прохода коллектора `PersonsService` сообщает
  наблюдателю (протокол `PersonCollectionObserver` в `MakoshPersons`,
  реализует `PersonsHost`) список созданных персон по книгам; хост ставит
  запуски `book:<id>` для книг с флажком. Персона, уже имеющая скетч,
  автоматически повторно не обогащается (моё решение). Почта, WhatsApp,
  Teams, спам и скрытые — никогда.
- Отключение флажка или модуля не трогает уже предложенное.

### Ключи сторонних API

Список известных ключей — `HIBP_API_KEY`, `VERIPHONE_API_KEY`,
`WHOXY_API_KEY` (имена параметров flowsint). Ввод в Настройках → Keychain →
попытка `createKey` (`POST /api/keys/create`); имена существующих ключей
читаются `GET /api/keys` (значения сервер не отдаёт). Замена — `DELETE`
старого id и `create`; `unknown` → чтение списка. Обогатители, требующие
отсутствующий ключ, в диалоге недоступны.

### Удаление

- Удаление персоны и «Удалить везде» ставят попытку `deleteSketch`
  (`DELETE /api/sketches/<id>`), если скетч есть; `unknown` → чтение скетча
  (404 → подтверждено). Строка `persons_osint_sketches` остаётся с пометкой
  `deletedAt`.
- Команда «Удалить данные OSINT…» в карточке: `deleteSketch` + удаление
  предложенных и отклонённых наблюдений этой персоны; подтверждённые
  остаются (это уже значения пользователя). Identity `osint/…` уходит в
  прежние.
- Отключение модуля ничего на сервере не удаляет.

### Попытки и состояние

`persons_osint_attempts`: `queued → sent → confirmed | rejected | unknown`;
вид `createSketch | addNode | launch | createKey | deleteKey | deleteSketch`;
`payload` — что нужно, чтобы найти запись при проверке (тип и первичное
поле узла, имя обогатителя, id скетча), **без телефонов и адресов в явном
виде** (только их SHA-256 для сверки, моё решение); ответ — id узла, id
задачи или id ключа; `failure` — код и стадия. После перезапуска Makosh
`sent` → `unknown`. Шаги установки хранятся отдельно в
`persons_osint_installs` (вид шага, состояние, сообщение без секретов).

Коды ошибок (`OSINTFailure`): `disabled`, `notInstalled`, `sshUnreachable`,
`sshAuthFailed`, `hostKeyMismatch`, `dockerMissing`,
`installFailed(stage)`, `healthTimeout`, `apiRejected(code, stage)`,
`unknownOutcome(stage)`, `invalidResponse(stage)`, `tooLarge`, `storage`.

## Интерфейс

- **Карточка персоны**, новый раздел «OSINT» ниже прежних значений:
  строка состояния («не обогащалась» / «обогащена <дата>, <n> находок» /
  «идёт запуск…» / «ошибка: <код>»), кнопка «Обогатить (OSINT)…», ссылка
  «Открыть граф», меню «Удалить данные OSINT…». Предложенные находки
  группами «Адреса и телефоны», «Соцсети», «Утечки», «Телефон», «Домены»,
  «Аватар»: значение, источник (обогатитель, дата), кнопки «Принять»,
  «Отклонить»; подтверждённые — тем же списком без кнопок; «ранее убрано»
  — пометкой. Для открытых попыток запуска — «Проверить» и «Отказаться».
- **Диалог запуска**: чекбоксы значений (адреса, телефоны, username, имя),
  чекбоксы обогатителей с пометками «нужен ключ <имя>», текст о передаче
  данных на сервер `<хост>` и сторонним сервисам, «Запустить».
- **Настройки → Персоны**, новая секция «OSINT-модуль (flowsint)»:
  переключатель модуля; поля хост, порт (22), логин, пароль (SecureField;
  сохраняется в Keychain сразу); «Проверить соединение» (показывает
  отпечаток хост-ключа при первом подключении с кнопками «Доверять» /
  «Отмена»; затем «docker есть/нет», «flowsint установлен: <тег>/нет»);
  «Развернуть модуль» / «Обновить до <тег пина>» с журналом шагов по
  строкам и индикатором; состояние («работает, v…», «не отвечает»);
  «Открыть веб-интерфейс» (браузер на `http://127.0.0.1:<порт туннеля>/`)
  и «Скопировать пароль веб-интерфейса» (служебный пользователь — единственное
  место, где секрет уходит пользователю, в буфер обмена, по его клику);
  ключи API: строки `HIBP_API_KEY`, `VERIPHONE_API_KEY`, `WHOXY_API_KEY` с
  состоянием «задан / не задан», «Задать…», «Удалить»; набор обогатителей
  по умолчанию (чекбоксы); «Открытые попытки OSINT» с «Проверить» /
  «Отказаться». У строк книг — флажок «Обогащать автоматически» (только у
  книг).
- Расхождения с эталоном раздела фиксируются в `docs/reference-interface.md`.

## Хранение

Таблицы в схеме раздела «Персоны» (`PersonsStoreSchema`, версия схемы +1):

- `persons_osint_settings(id=1, data JSONB)` — хост, порт, логин, отпечаток
  хост-ключа, id сервера (UUID, выдаётся при первом сохранении), id
  расследования, установленный тег и SHA, время установки, включён ли
  модуль, набор обогатителей по умолчанию, порт туннеля не хранится.
- `persons_osint_sketches(person_id UUID PK, sketch_id TEXT, created_at,
  deleted_at)`.
- `persons_osint_runs(id UUID PK, person_id, trigger TEXT, state TEXT,
  created_at, started_at, finished_at, failure JSONB, found INTEGER,
  truncated BOOLEAN)`.
- `persons_osint_attempts(id UUID PK, run_id UUID NULL, person_id UUID NULL,
  kind TEXT, state TEXT, payload JSONB, response JSONB, failure JSONB,
  created_at, updated_at, resolved_at)` с индексом по `(state, created_at)`.
- `persons_osint_installs(id UUID PK, state TEXT, target_tag TEXT,
  target_sha TEXT, steps JSONB, created_at, finished_at)`.
- Поле `enrichAutomatically` в JSON `PersonBook` (по умолчанию `false`).
- Наблюдения и identity — в существующих структурах `Person`
  (`observations`, `identities`); `ObservationStatus.rejected` — новое
  значение.

Keychain `org.makosh.osint.v1`: учётные записи `ssh-password`,
`service-password`, `env.AUTH_SECRET`, `env.MASTER_VAULT_KEY_V1`,
`env.NEO4J_PASSWORD`, `env.POSTGRES_PASSWORD`, `key.<ИМЯ>`; в QA — хранилище
в памяти, как у календаря.

## Сервис и модули

- `MakoshOSINT` (новый target; зависимости `MakoshCore`, `CPostgres`,
  `NIOSSH` из `swift-nio-ssh`, `NIO`/`NIOPosix`):
  `OSINTModels` (настройки, запуск, попытка, установка, ошибки),
  `OSINTStore` (таблицы выше), `OSINTCredentialVault`,
  `OSINTSSHSession` (актор: сессия, хост-ключ, exec, туннель),
  `FlowsintAPI` (протокол) и `FlowsintClient` (REST через туннель, JWT с
  повторным входом при 401), `FlowsintInstaller`, `OSINTGraphMapping`
  (чистая), `OSINTService` (актор: один раннер запусков, установка,
  ключи, проверка `unknown`, удаление), `FlowsintSynthetic` (реализация
  `FlowsintAPI` в памяти со сценарием находок), `OSINTSyntheticSSHServer`
  (сервер `swift-nio-ssh` на loopback со сценарием команд для установщика),
  `OSINTQAIsolation`, `Presentation/OSINTWorkspaceModel` (MainActor,
  только координация).
- `MakoshCore`: `ObservationStatus.rejected`; `PersonStore` получает
  `addProposedObservations(personID:_:)`, `setObservationStatus`,
  `acceptObservation` (ручное значение + confirmed) и
  `removeObservations(personID:source:)` — append-only для значений, статус
  наблюдения меняется на месте.
- `MakoshPersons`: `PersonBook.enrichAutomatically`; протокол
  `PersonCollectionObserver` (созданные персоны по книгам после прохода);
  `PersonsService.deletePerson`/`deleteEverywhere` вызывают наблюдателя
  удаления (`PersonDeletionObserver`) — оба протокола живут в
  `MakoshPersons`, реализует `PersonsHost`. Модуль по-прежнему не
  импортирует каналы и не импортирует `MakoshOSINT`.
- `Sources/MakoshApp/Persons`: `PersonsHost` создаёт `OSINTService`, передаёт
  ему `PersonStore`, подписывает наблюдателей; `PersonCardSections` — раздел
  «OSINT» и диалог запуска; `PersonsSettingsView` — секция модуля;
  `PersonsSyntheticPreview` — сид OSINT.
- Границы потоков: SSH, HTTP, SQL, Keychain — вне MainActor;
  `OSINTWorkspaceModel` только читает снимки и отдаёт команды; обратные
  вызовы `swift-nio` не наследуют изоляцию.

## Синтетический QA

`--persons-synthetic-preview` расширяется: `PersonsHost` в этом режиме
получает `FlowsintSynthetic` вместо `FlowsintClient` и
`OSINTSyntheticSSHServer` на loopback вместо LXC; Keychain — в памяти.
Сид: настройки модуля указывают на синтетический SSH, установщик проходит
все шаги по сценарию (`docker version` отвечает, `git` «клонирует»,
`compose up` «поднимает», health отвечает), регистрирует пользователя,
создаёт расследование; затем для Анны выполняется ручной запуск: по адресу
— Gravatar и одна утечка, по username — два соцаккаунта, по телефону —
оператор; одна задача остаётся `unknown`. В окне видно: секция модуля
«установлен v<пин>», раздел «OSINT» карточки Анны с предложенными
находками, открытая попытка с «Проверить». `scripts/run-persons-qa.py`
флаги не меняет; проверка по базе — `scripts/test-persons-qa.py`
дополняется таблицами OSINT. Осмотр окна — за пользователем.
