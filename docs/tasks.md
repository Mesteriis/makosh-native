# Раздел «Задачи» и Jira

Дизайн: `superpowers/specs/2026-11-07-tasks-section-design.md`; план:
`superpowers/plans/2026-11-07-tasks-section.md`. Первая часть направления
«Задачи»: локальный домен по правилам TaskOrchestrator, Jira Cloud как первый
провайдер, учёт времени. Вторая очередь перечислена в конце.

## Что это

Одно хранилище задач с двумя витринами. «Мои» — локальные задачи и задачи
Jira, назначенные на пользователя или с упоминанием, с локальным слоем
(статус, приоритет, список, теги, срок, зависимости, заметки, время).
«Jira» — задачи подключения колонками по статусам workflow проекта, с теми
переходами, которые Jira разрешает. Одна задача видна в обеих витринах без
второй записи.

## Модули

- `MakoshJira` — протокольный слой Jira Cloud (REST v3, почта + API-токен).
  Транспорт, сессия и разбор дат перенесены из `MacTowerWorkTracking`
  (`Dependencies/Jira.lock.json`, ревизия `317eeafb`, MIT); клиент v3,
  адаптер, ADF и модели написаны заново. `JiraAdapter` — общий протокол для
  Cloud, будущего Data Center и синтетики. Ошибки несут код и стадию, не
  тело ответа, не URL и не токен.
- `MakoshTasks` — домен (`TaskDomain`), быстрый ввод (`TaskQuickEntry`,
  `TaskDateParser`), хранилище PostgreSQL в схеме приложения (`TaskStore`,
  таблицы `tasks_*`), undo (`TaskUndoHistory`), журнал попыток
  (`TaskJiraAttemptJournal`), зеркало (`JiraMirror`), подключения и токены
  (`JiraConnectionRegistry`, `JiraTokenVault` → Keychain
  `org.makosh.jira.tokens.v1`), время (`TaskTimeService`), сервис
  (`TasksService`) и модель раздела (`TasksWorkspaceModel`).
- `Sources/MakoshApp/Tasks` — `TasksHost` в окружении, витрины, карточка,
  быстрый ввод, таймер в строке состояния, Настройки → Задачи, окно QA.
  Внутри `MakoshTasks` и этих файлов Swift-овский `Task` пишется как
  `_Concurrency.Task`: тип задачи назван `Task` по спеке. `MakoshApp.swift` и
  `WorkspaceView.swift` модуль не импортируют и идут через `TasksHost`.

## Правила домена

- Статусы `inbox → active → done → cancelled → inbox`; задача с открытыми
  зависимостями заблокирована: цикл `inbox → cancelled`, перевод в
  `active`/`done` отклоняется с причиной «Ждёт: …». `cancelled` и
  отсутствующая задача не блокируют. Закрытие активирует зависимые
  `inbox`-задачи, у которых закрыты все блокеры. Циклы зависимостей
  отклоняются.
- Просрочка — срок строго меньше сегодня и статус не `done`/`cancelled`.
  «Отложить» — срок +1 день от max(срок, сегодня), счётчик +1. `done`
  ставит `completedAt`, уход снимает; повторный `done` ничего не делает.
- Удаление мягкое. Undo — 5 шагов в памяти по 12 часов; шаг недоступен,
  если ревизия задачи с тех пор менялась; история сбрасывается, когда
  зеркало применило внешние изменения.
- Быстрый ввод: `Название @список #тег !1 ^срок ~код`. Даты: `сегодня`,
  `завтра`, `вчера`; день недели строго после сегодня; `+3d/+2w/+1m`;
  `20` — ближайшее 20-е; `20.04` — ближайшая будущая; `20.04.2026`;
  `5янв`/`jan5`. Нераспознанная дата и неизвестная зависимость остаются в
  названии и подсвечиваются в предпросмотре.
- Короткий код — 5 символов Crockford Base32 от UUID; коллизия проверяется
  до INSERT (ошибка внутри транзакции отравила бы её).

## Jira

- Подключение: HTTPS-адрес сайта без пути, почта, API-токен (только
  Keychain), период опроса (по умолчанию 5 минут), «Искать упоминания»,
  «Предлагать worklog». «Проверить» зовёт `myself`.
- Зеркало: JQL `(assignee = currentUser() OR comment ~ "<accountId>")
  ORDER BY updated ASC`, инкрементально с `updated >= <последний успех −
  10 мин>`, полный проход при подключении и раз в сутки. Страницы по 50
  через `nextPageToken`; недействительный курсор — один сброс страницы;
  `429`/`503` — `Retry-After` или backoff 5 с → 1 ч, применённые страницы
  остаются. Если Jira отклонила `comment ~`, зеркало продолжает без
  упоминаний и помечает это в подключении.
- Применение: новая задача — локальная `inbox`, приоритет 4, ссылка на
  задачу; существующая — новая версия наблюдения, название и ссылка
  следуют Jira, пока пользователь их не менял; категория «Готово» → локальный
  `done`, если он не `done`/`cancelled`. Ушедшая из выборки: `kept` при
  локальной активности (активный статус, таймер, незасланное время, попытка в
  полёте), иначе `none`; история и наблюдения остаются. Витрина «Jira»
  показывает `assigned`, `mentioned`, `kept`.
- Пять действий — попытки в `tasks_jira_attempts`: `queued → sent →
  confirmed | rejected | unknown`, `unknown → confirmed | rejected` только по
  «Проверить» (сверка: worklog по автору, началу ±1 с, длительности и
  примечанию; комментарий по автору и тексту; переход по статусу; поля и
  исполнитель по полям задачи) или «Отказаться». Одна открытая попытка на
  (задача, вид). При старте `sent` → `unknown` («перезапуск»). Отказ Jira
  `4xx` (кроме 408/409) — `rejected`; обрыв, таймаут, 5xx — `unknown`.
- Переход: поля типов `string`, `number`, `date`, `option`, `resolution`
  рисуются; обязательное поле другого типа блокирует отправку с надписью
  «заполняется только в Jira». Описание правится только в простом ADF
  (абзацы, текст, переносы, упоминания, простые списки); с таблицами или
  вложениями — только чтение. Комментарии отправляются как ADF из текста.
  Исполнитель — поиск по назначаемым пользователям проекта от 2 символов,
  «Снять назначение» шлёт `null`.

## Время

- Записи `tasks_time_entries`: источник таймер/вручную/встреча, начало,
  длительность (кратна минуте, минимум одна), примечание, встреча,
  попытка и `worklogID`. Один таймер на приложение (`tasks_timer`),
  переживает перезапуск; остановка — черновик с правкой; «Списать в Jira»
  по умолчанию включено для задач Jira, если подключение не отключило
  предложение. Черновик имеет id записи: повторное подтверждение даёт
  `duplicate`, а не вторую запись.
- Запись с подтверждённым worklog закрыта для правки длительности, даты и
  удаления; меняется только примечание. Следующее чтение worklog задачи
  обновляет запись по id или помечает «удалено в Jira».
- Встречи Telemost: «Списать время…» в карточке встречи — черновик на
  задачу, чей ключ один в названии или заметках (регулярное выражение
  MacTower), иначе выбор задачи; «Открыть встречу» предлагает запустить
  таймер на найденную задачу, отказ ничего не запускает.

## QA

- `scripts/run-tasks-qa.py --bundle … --launch` стадирует отладочный бандл
  (`org.makosh.tasks.qa`) и запускает `--tasks-synthetic-preview` с одной
  схемой `qa_tasks_<suffix>` на loopback PostgreSQL. Сид — 12 локальных
  задач (просроченная, заблокированная, цепочка, списки, теги) и
  синтетическая Jira в памяти: 6 задач в проектах QA и OPS, переход Done с
  обязательным `resolution`, задача с таблицей в описании, задача только по
  упоминанию, `failNext` для показа состояния «неизвестно».
- Живая Jira — только по команде пользователя на выбранном им подключении и
  задаче; первый worklog — одна минута на тестовую задачу.

## Вторая очередь

Планер дня; повторы; именованные цепочки с прогрессом; персоны → контакты;
уведомления о назначениях и упоминаниях; карточка «задача» для ИИ; Data
Center (PAT, OAuth 1.0a из MacTower); правка и удаление worklog из Makosh;
ставки, сводки по месяцам, счета и оплаты; резервная копия задач;
синхронизация между устройствами по журналу версий.
